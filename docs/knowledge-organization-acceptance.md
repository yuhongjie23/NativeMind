# DeepSeek 知识整理实测

适用于 2026-11-10 的本地开发代码；不是已发布 v2.0.0 安装包的功能说明。普通桌面版支持此功能，Anna Local 纯本地版和浏览器演示版保持禁用。以下是待执行的人工验收步骤，不是已经完成的真实模型验收结果。

## 启动与材料

1. 在工程目录运行 `npm run desktop`。已有桌面开发窗口时，先确认它使用当前源码。
2. 在设置中配置并测试自己的 DeepSeek API Key，再单独开启“AI 知识整理（仅 DeepSeek · 关联与卡片）”。内容会发送给 DeepSeek，并可能计费。
3. 导入 `tests/integration/fixtures/knowledge-organization-acceptance.txt`。这是合成学习材料，包含中文二分查找笔记、带正确答案的数组练习与英文 lower-bound 笔记，不含个人信息。
4. 打开该笔记，先查看“下一段”的范围，然后点击“DeepSeek 整理为知识卡片”。每次点击只请求一批，不会自动跑完整本书。

## 第一轮：卡片质量与确认

- 预览应显示本段范围；只有后续段落才显示附带上段上下文的提示。
- 检查是否保留有序输入、区间端点、返回位置与存在性区别等必要条件。不要仅凭标题看起来合理就判断成功。
- 正文可以是 AI 的概括；原文摘录必须是资料中的连续原句。来源存在的程序校验不能证明概括一定正确。
- 相似练习最好概括为少量有意义的知识点，而不是一题一张重复卡片。每批最多 8 张，不要求模型固定输出 8 张。
- 修改一个标题和正文、取消勾选另一张，确认后只保存保留的卡片。原笔记不变。
- 打开卡片并点击“定位原文”，应跳到原笔记的支持段落。特别检查第二批以后的卡片：定位应使用整篇文档坐标。
- 材料中没有红黑树删除或并发哈希表实现；不应生成这些主题的算法步骤。

## 第二轮：长文继续与中断

- 保存第一批后，进度应增加，按钮变为“继续整理下一段”；不应自行开始下一批。
- 关闭再打开笔记，或重启桌面 App，进度应保留。继续处理时不要重复发送全文。
- 在下一批生成或预览阶段取消：这批不应保存卡片、推进进度。再次点击仍处理同一段。
- 如果一批没有卡片，选择“取消”应停留本段；只有选择“本段不建卡，确认继续”才推进。也可以取消勾选全部卡片后明确确认不建卡。
- 全文范围完成后，按钮停止继续请求。这个状态仅代表逐段处理完毕，不代表所有知识点都已覆盖或事实核验成功。
- 点击“重新检查全文（保留卡片）”应只清空处理进度。已有卡片仍可阅读，同版本同原文区间再次采用时应复用，并保留你的编辑。

## 第三轮：语言与配置

- 切换英文界面。新生成的卡片标题、概括正文应为英文；原文摘录保持材料原语言，界面按钮与提示应为英文。
- 关闭 AI 知识整理后，入口不可发起新请求；普通笔记阅读与本地检索仍可用。
- 缺少 Key 时不可开启该功能。服务不可用时应明确失败，不能出现本地模型伪造的成功卡片。

## 第四轮：跨笔记主题组合

- 准备两篇分别解释二分查找有序前提、lower_bound 边界的短笔记，再准备一篇无关的光合作用笔记。
- 在知识库“笔记”页展开“组合为主题页”，选择 2–8 篇。界面应说明只发送每篇前 1,500 字符；长篇材料建议先提取卡片。
- 查看模型的分组、关联理由和原文引用。相关笔记可以组合，但不应强行加入无关材料，不能把不同边界条件说成完全相同。
- 修改主题标题、取消不合适的分组，再确认。应新增独立主题页，原笔记内容保持不变；点击引用应定位到正确来源。
- 同一组来源版本再次组合应复用已有主题页并保留你的编辑。如果需要重新选择分组，可删除主题页后重新组合。
- 取消或拒绝不新增主题页；删除主题页不删除原笔记。修改或删除来源后，主题页应保留摘录并提示来源已变化或不存在。
- 程序只校验引用和来源一致性，真实模型的分组合理性与关联理由是否充分仍需人工判断。

## 第五轮：查看反向引用（无需调用模型）

- 使用已有卡片或主题页，打开对应来源笔记，展开“哪些笔记引用了这里”。应看到引用笔记的当前标题、摘录和主题分组理由；同一主题有多个分组引用时不重复列出主题页。
- 点击引用笔记标题，应打开该卡片或主题页；再从来源导航返回原笔记。普通笔记详情和搜索结果的阅读弹窗都应提供此入口。
- 修改来源正文，引用区应提示历史版本；删除引用笔记后刷新，它应从列表消失，原笔记保持不变。
- 超过 20 条引用时检查上一页/下一页；切换英文界面后检查按钮和状态提示。关闭 DeepSeek 整理开关后，已保存引用仍可查看。
- 此入口不统计未标记为链接的普通文字，也不代表 AI 的关联理由已经经过事实核验。正文 `[[链接]]` 验收见下一轮。桌面实际点击体验待人工验收。

## 第六轮：正文双向链接（无需 DeepSeek）

- 新建标题为“二分查找”的笔记，再新建“边界练习”，正文写入 `先复习 [[二分查找]]，再讨论 [[二分查找|边界条件]]。`。阅读时保留原始链接语法，点击任一链接应打开“二分查找”。
- 在“二分查找”展开反向引用，应仅列出一次“边界练习”，包含正文上下文；点击回去应定位首次链接。搜索结果阅读弹窗与图谱阅读器中的正文链接也应可点击。
- 在“边界练习”按 Ctrl+F 搜索“二分查找”，检查多次匹配跳转与高亮；关闭重开检查阅读位置。不应因增加链接造成原文坐标偏移。
- 新增另一篇同名“二分查找”后，点击应提示重名，不能任意跳转；这类不明确的正文链接不出现在任一同名笔记的反向引用中。
- `[[不存在的标题]]` 应提示缺失，不自动建笔记。英文标题区分大小写。通过新“修改标题与链接”入口改名时应一起更新正文链接（见下一轮）；直接改库或绕过该入口不自动修复。
- 代码示例、转义链接和普通提及不计入反向引用。当前不支持 `[[标题#章节]]`、块引用或 `![[嵌入]]`；保留为文本。
- 切换英文界面检查缺失/重名提示；关闭云端 AI 后仍可正常使用。真实桌面点击与大库滚动性能仍待人工验收。

## 第七轮：改名与正文链接维护（无需 DeepSeek）

- 在“二分查找”打开“修改标题与链接”，输入“有序数组二分查找”，点击“预览受影响的链接”。应看到关联笔记名称、更新数量和每篇最多 3 处修改前后示例；此时原文与标题仍未改变。
- 取消预览或关闭笔记，不应写入。重新预览后点击“保存改名与链接”，来源标题及其他正文中的目标标题应一起更新，`|边界条件` 等标签保持不变。
- 点击更新后的正文链接应正常打开目标；Ctrl+F、原文定位和 PDF 页码仍应对齐。反向引用应显示新的记录。
- 原始 PDF/Markdown 文件、卡片来源摘录、主题页历史引用保持原样；正文内容变化后，旧摘录可能正确地显示版本过时提示。
- 新标题与其他笔记重名时应阻止操作。原标题有重名时，应提示仅改当前笔记，不随意重写其他笔记链接。
- 预览后在另一处修改关联笔记，再保存应要求重新预览，不覆盖新内容。切换英文界面检查所有按钮、预览与失败提示。
- 保存后正文变动的笔记应排队重建索引。断电/磁盘故障的真实机器测试尚未进行；事务回滚已用自动测试注入写入失败验收。撤销入口见下一轮。

## 第八轮：撤销改名与查找操作

- 成功改名后，在同一入口点击“撤销最近一次改名”，标题、正文链接、别名和页码应恢复；反向引用跟随刷新。只能撤销本次运行最近一次成功改名，重启后入口消失。
- 改名后修改任一参与笔记、增加指向新标题的引用，或让其他笔记占用原标题，撤销应明确失败并保留当前内容；不能用全文替换强行覆盖。
- 预览期间仅后台索引状态变化，不应再被误判为笔记编辑；保存后保持最新索引状态。正文变化时正常重新排队。
- 文档内 Ctrl+F 搜索链接中的词，检查上/下一个匹配、键盘 Tab 和 Enter：一条链接即使内部高亮也只能有一个焦点入口。
- 2026-11-10 已用两篇合成笔记完成独立浏览器演示环境的实际点击验收：改名预览/保存、两处链接更新、撤销恢复、反链跳回、Ctrl+F 两处切换和正文链接跳转。此结果不替代原生桌面、真实模型或全新电脑验收。
