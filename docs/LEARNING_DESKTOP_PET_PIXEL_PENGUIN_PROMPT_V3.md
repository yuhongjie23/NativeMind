# NativeMind 圆企鹅学习桌宠生成提示词 V3

## 0. 设计结论

旧版鸭子方向全部取消。新角色是一只原创的圆企鹅像素玩偶，暂定名为 **墨团**，内部 ID 为 `motuan-penguin-v01`。

它的核心不是“企鹅元素堆叠”，而是以下四个稳定特征：

```text
头身一体的圆润蛋形轮廓
烟灰绿外羽与暖米灰脸腹
短小陶土色喙、灰粉色腮红
安静、迟钝一点点、低打扰的表情语言
```

参考图只用于提取“圆脸、粗像素轮廓、表情可读、九宫格一致性”的方法，不复制参考图中的猫耳、虎斑、五官比例、配色或具体表情画法。

---

## 1. 参考图中应该保留与舍弃的部分

### 保留

- 正面轮廓饱满，缩小后仍能快速识别。
- 眼睛、嘴部和头部倾斜承担大部分情绪表达。
- 每个表情都维持相同的头部大小和五官位置。
- 使用有限色阶塑造体积，而不是依靠模糊渐变。
- 九宫格有利于先锁定角色表情，再继续做全身动作。

### 调整

- 参考图的纯黑描边过重，改为深烟绿灰描边。
- 参考图的黑白与橙色对比偏强，改为烟灰绿、暖米灰、陶土粉的低饱和组合。
- 不使用猫耳、虎斑、猫鼻、胡须和猫爪动作。
- 不使用特别巨大的动漫眼睛，避免表情过于吵闹。
- 不把白色背景当成透明背景；白底仅用于角色设定图。

## 2. 墨团的角色 Style DNA

### 2.1 角色定位

```yaml
id: motuan-penguin-v01
display_name: 墨团
species: 原创圆企鹅像素玩偶
role: 安静的学习陪伴桌宠
temperament:
  - 温和
  - 略微迟钝
  - 好奇
  - 低打扰
  - 不催促
  - 不评判
```

### 2.2 固定轮廓

- 头部和身体连成一个完整蛋形，没有明显脖子。
- 整体略微下宽上窄，像一颗柔软的圆石或布偶。
- 角色全身宽高比约为 `0.82:1`，不能细长。
- 头脸约占全身高度的 `48%`，腹部约占 `35%`，脚部不超过 `8%`。
- 两侧鳍状小翅膀短而圆，贴近身体，不像人类手臂。
- 两只脚小、扁、短，只负责接地，不突出鞋子感。
- 正面时身体近乎对称，但允许一侧小翅膀略低 `1-2` 像素，增加自然感。
- 不画耳朵、头顶羽冠、长尾巴、长腿、手指或明显脖子。

### 2.3 固定脸型

- 额头深色羽毛形成一个非常浅的圆弧，不做尖锐 M 字发际线。
- 暖米灰脸部斑块像一颗横向圆润的小爱心，但边缘必须含蓄，不画成符号。
- 腹部暖米灰斑块与脸部自然衔接，形成企鹅识别特征。
- 眼睛是深墨绿色的小椭圆像素块，大小稳定，不做超大动漫眼。
- 每只眼睛最多保留一个极小的灰绿色高光像素。
- 喙短、扁、圆，使用低饱和陶土色，不使用明黄色。
- 腮红是两小块灰粉色像素，面积克制。
- 开心主要通过眼睛弯曲、头部轻倾和身体轻微压缩表达，不露出整排牙齿。

### 2.4 固定材质与像素语言

- SNES 时代启发的精细 16 位像素艺术。
- 使用明确像素块、阶梯轮廓和有限色阶。
- 不做“高清插画加像素滤镜”的假像素效果。
- 每个部位使用 3 到 5 个明暗层级，整套角色不超过 64 色。
- 阴影使用分层像素块，不使用连续柔焦渐变。
- 边缘清晰，禁止抗锯齿毛边、半透明脏边和重采样模糊。
- 光源始终来自左上方，右下方使用柔和的烟灰褐阴影。
- 角色表面是哑光软布偶质感，不是塑料、金属或湿亮羽毛。

### 2.5 固定配色

```yaml
outline: "#293835"       # 深烟绿灰，不用纯黑
outer_dark: "#3F4F4C"    # 烟灰绿外羽
outer_mid: "#5C6B66"     # 中间层外羽
outer_light: "#748078"   # 左上方柔和亮面
face_belly: "#D4CEB9"    # 暖米灰脸腹，不用纯白
face_light: "#E3DDC9"    # 米灰亮面
face_shadow: "#AAA38F"   # 米灰阴影
beak_feet: "#BF775E"     # 低饱和陶土色
beak_light: "#D59272"    # 喙和脚的柔和亮面
blush: "#C1847E"         # 灰粉腮红
eye: "#1F2C2A"           # 深墨绿眼睛
tongue: "#B96270"        # 仅用于吐舌表情
```

白色只能作为角色设定图的背景色，不能出现在企鹅腹部和眼白的大面积区域中。

## 4. 3×3 九宫格表情图提示词

这张图用于冻结五官、情绪范围和头部角度，不是最终动画资源。

### 完整提示词

```text
使用提供的“墨团”角色母图，生成一张 16 位像素艺术风格的角色表情图集，纯白色背景，严格采用 3×3 九宫格排版，展示同一只原创圆企鹅像素桌宠的九种不同表情。每一格以 64×64 逻辑像素绘制，角色为头部与上半身近景，头部大小、脸部轮廓、眼睛间距、喙大小、腮红位置、额头弧线和配色在九格中完全一致。角色外羽为低饱和烟灰绿，脸部为暖米灰，喙为陶土粉橙色，腮红为灰粉色，眼睛为深墨绿色；禁止纯黑和纯白形成刺眼反差。

第一排从左到右：
1. 双眼弯起，短喙微张，只露出一点很小的暗玫瑰色舌尖，表现克制而开心的笑容。
2. 嘴巴轻微张开，眼睛平和看向用户，像在温柔地说一句很短的话。
3. 一侧小翅膀靠近脸颊，目光稍微移开，腮红略深，表现含蓄害羞。

第二排从左到右：
4. 正面平静的中性表情，嘴巴闭合，眼睛自然睁开，作为角色标准基准脸。
5. 双眼微眯成柔和弧线，嘴角轻轻上扬，表现放松和满足。
6. 脑袋向右轻轻倾斜约 8 度，一只眼略高，表现安静的好奇。

第三排从左到右：
7. 双眼略微睁大，短喙微张，露出一点小舌尖，表现活泼但不尖叫。
8. 双眼闭合，短喙张开打一个很大的哈欠，身体微微缩起，表现困倦慵懒，不出现 Z 字符。
9. 头部转向左侧三分之一角度，眼睛望向远处，嘴巴闭合，表现若有所思。

整体采用 Super Nintendo（SNES）复古 16 位像素风格，像素线条干净，清晰阶梯轮廓，比例统一，单格构图一致，最多 64 色，阴影使用分层像素块而不是平滑渐变，哑光柔软玩偶质感，经典卡通感但适合成人学习软件。九个角色互不重叠，格子之间留出均匀白色间距，不生成格线、编号、文字、标签、Logo 或水印。
```

### 九宫格负面提示词

```text
禁止九格角色变成不同企鹅，禁止身体颜色变化、脸型变化、眼睛间距变化、喙大小变化、腮红消失、头部忽大忽小；禁止猫耳、鸭嘴、黄色身体、纯黑白高反差；禁止多余翅膀、多余眼睛、手指和牙齿；禁止文字、编号、表情名称、格线、对话框、水印；禁止3D、渐变、柔焦、抗锯齿、照片、矢量风和高饱和颜色
```

### 实际使用方式

```text
生成九宫格候选
-> 选择角色最稳定的一张
-> 分别裁出九个表情
-> 统一裁切为64×64逻辑像素
-> 用最近邻算法放大预览
-> 选出neutral、happy、curious、sleepy四个基准表情
-> 作为全身动作的表情参考
```

如果即梦无法直接输出真正的 `192×192` 像素图，可以先生成高分辨率正方形图，再在像素编辑器中把每格重绘或最近邻缩小到 `64×64`。不要直接使用带模糊边缘的高分辨率“伪像素”结果。

## 5. 八组全身动作设计

下面共 8 组。前 4 组是桌宠环境动作，后 4 组对应学习与 Agent 状态。

### 动作 1：趴着休息 `rest_prone`

**用途：** 用户专注、长时间无操作或宠物自动休息。

**动作描述：**

```text
墨团从站立蛋形缓慢降低重心，小脚收进身体下方，两侧小翅膀贴住身体，整个身体向前摊成一颗低矮、柔软的椭圆小团。脸颊轻轻贴近前方，双眼闭合，短喙部分藏在暖米灰脸部下缘。趴下后只保留1到2像素的缓慢呼吸起伏，像一个安静的企鹅布偶，不出现枕头、被子、床或Z字符。
```

**建议关键帧：** 站立、半蹲、前倾、完全趴下、轻微吸气、轻微呼气。

### 动作 2：鼠标拖动时被拎起 `carried`

**用途：** 用户按住宠物并拖动位置。

**动作描述：**

```text
墨团进入被鼠标安全提起的悬空姿态，但画面中不绘制鼠标、手或抓取工具。角色头顶保持原有圆形轮廓，身体因悬空只纵向拉长2到3像素，两侧短翅膀自然向下垂，小脚离开地面并轻轻并拢，眼睛向上看向抓取方向，表情有一点意外但不害怕。拖动过程中身体可左右滞后2像素，像柔软玩偶被轻轻提起，不表现疼痛、挣扎或勒住脖子。
```

**建议关键帧：** 刚离地、稳定悬空、向左拖动滞后、向右拖动滞后、准备放下、柔和落地。

### 动作 3：空闲时打一个滚 `roll_once`

**用途：** 空闲一段时间后低概率触发的一次性环境动作。

**动作描述：**

```text
墨团先左右观察，身体轻轻向一侧倾斜，然后收起小翅膀和脚，像圆球一样缓慢侧滚一整圈。滚动中暖米灰腹部、烟灰绿背部和小脚的前后关系清晰，角色不改变颜色和体积。滚完后身体轻轻压扁，再恢复稳定站姿，眨一次眼，表现略微迟钝又满足。动作不快速、不连续翻滚、不产生灰尘、星星或速度线。
```

**建议 8 帧：** 准备倾斜、侧倒、四分之一滚、背部朝前、四分之三滚、腹部回正、压扁落地、站起眨眼。

### 动作 4：看向用户 `look_at_user`

**用途：** 用户打开应用、移动鼠标靠近宠物或等待交互。

**动作描述：**

```text
墨团身体与脚底位置保持不变，先让眼神从侧下方移动到屏幕前用户，再让头部轻轻抬起并倾斜约5度。眼睛自然睁开，停留片刻后慢慢眨眼，短喙保持闭合，腮红不改变。动作表达“我看到你了”，不是催促、索要关注或发出警报，不挥手，不出现气泡和标点符号。
```

**建议关键帧：** 侧视、眼神回中、轻抬头、直视用户、慢眨眼、恢复中性。

### 动作 5：安静陪读 `study_loop`

**用途：** 番茄钟进行中，或 Agent 处于 `Running`。

**动作描述：**

```text
墨团坐在一本没有文字的迷你打开书本前，身体保持圆润，双翅轻轻压在书页两侧，眼睛低头看书。每隔几帧眼神从左页移动到右页，偶尔慢眨一次眼，身体只有非常轻的呼吸变化。不要让企鹅长出手指，不写字，不快速翻页，不生成可读文字。
```

**建议关键帧：** 中性低头、看左页、看右页、轻眨眼、翼片微调、回到中性低头。

### 动作 6：等待用户输入 `needs_input`

**用途：** Agent 需要用户确认、选择或补充信息。

**动作描述：**

```text
墨团从低头陪读姿态慢慢抬头，一侧小翅膀抬到胸前，脑袋向右轻轻倾斜，眼睛看向用户，短喙微张。动作只播放一次，随后保持安静等待。表情是温和的“这里需要你看一下”，不能惊慌，不连续挥手，不出现问号、感叹号、红点或警报符号。
```

**建议关键帧：** 低头、抬眼、抬头、轻倾脑袋、小翅膀抬起、保持等待、慢眨眼、稳定结束。

### 动作 7：结果准备好 `ready`

**用途：** Agent 完成工作，或一段专注结束。

**动作描述：**

```text
墨团双眼弯成柔和短弧，身体轻轻向上弹起2到3像素，两侧小翅膀短暂张开，落地时身体横向压缩1像素后恢复蛋形。动作表达轻微开心和“已经好了”，不高跳，不连续庆祝，不生成彩带、奖杯、金币、星星或烟花。
```

**建议关键帧：** 中性、蓄力压低、轻弹起、翅膀张开、最高点、柔和落地、身体回弹、恢复中性。

### 动作 8：认真查看问题 `concerned`

**用途：** Agent 处于 `Blocked`，模型或工具暂时无法继续。

**动作描述：**

```text
墨团身体略微压低，眼睛向左下方看，短喙闭合，一侧小翅膀轻轻贴近脸颊，随后抬眼看向用户。表情是认真、有一点疑惑但仍然平静，像在一起检查问题。不能哭泣、愤怒、发抖、责怪用户，也不出现红叉、警告三角形或错误文字。
```

**建议关键帧：** 中性、身体压低、向下查看、翼片靠近脸颊、短暂停顿、抬眼、恢复一点高度、稳定结束。

## 7. 生产资源与项目兼容关系

### 7.1 九宫格不是最终 Sprite Sheet

```text
3×3 表情图：角色设计与表情参考
全身动作审核图：动作和关键帧参考
透明单帧 PNG：真正用于动画的中间资源
1536×1872 Sprite Sheet：最终放入 companion.assetBase 的生产资源
```

白底只用于方便比较角色一致性。正式单帧必须改为透明背景，并统一到：

```yaml
spritesheet_width: 1536
spritesheet_height: 1872
columns: 8
rows: 9
frame_width: 192
frame_height: 208
anchor_x: 96
ground_y: 188
background: transparent
```

基础角色包继续遵守现有 `8×9` 网格。`carried`、`roll_once`、`look_at_user` 在代码扩展完成前，先保存为独立的透明 PNG 帧序列，不要覆盖当前 72 格中的既有动作。

### 7.2 当前可直接复用的动作

现有 Manifest 已经支持：

```text
rest_prone     -> sleep_enter / sleep_loop
study_loop     -> study_loop
needs_input    -> needs_input
ready          -> ready / cheer
concerned      -> concerned
```

### 7.3 需要后续扩展代码的动作

以下三个动作目前不应假装已经接好：

```text
carried
roll_once
look_at_user
```

后续接入时需要在 `PetAction`、动作队列、场景调度器和 `pet-manifest.json` 中增加对应动作名。其中：

- `carried` 在鼠标按下并开始拖动时进入，释放时播放落地动作。
- `roll_once` 只在空闲状态低概率触发，一次播放后回到 `idle`。
- `look_at_user` 可由鼠标靠近、应用重新获得焦点或陪伴面板打开触发。
- Agent 只输出业务状态，不直接决定图片文件、帧索引、FPS 或坐标。

推荐先按以下目录保存扩展动作源文件，是否并入主 Sprite Sheet 等代码方案确定后再决定：

```text
<companion.assetBase>/source-extras/carried/
<companion.assetBase>/source-extras/roll-once/
<companion.assetBase>/source-extras/look-at-user/
```

### 7.4 最终制作顺序

```text
角色母图
-> 3×3表情图
-> 选定4个基准表情
-> 8组动作关键姿势
-> 每组逐帧生成
-> 统一为192×208透明单帧
-> 固定锚点和角色比例
-> 脚本打包Sprite Sheet
-> 更新Manifest
-> 最后再接入新增动作状态
```

不要让生图软件一次生成最终 `8×9` Sprite Sheet。它很难同时保证网格尺寸、透明边缘、角色比例和动作首尾衔接。最终网格应由脚本打包。

## 8. 第一轮只生成这些内容

先不要制作完整动画，第一轮只生成：

```text
1. 一张墨团正面三分之四完整母图
2. 一张3×3九宫格表情图
3. 一张趴着休息的全身关键姿势
4. 一张被拎起的全身关键姿势
5. 一张侧滚中段的全身关键姿势
6. 一张直视用户的全身关键姿势
```

通过标准：

- 六张图看起来必须是同一个角色。
- 缩小后仍能看出圆企鹅轮廓，而不是猫、鸭子或黑白色块。
- 颜色在书房或图书馆背景上有辨识度，但不突兀。
- 趴下、悬空和侧滚时仍然保留脸部斑块、短喙和小翅膀。
- 表情可读，但不会在番茄钟界面中抢走用户注意力。
