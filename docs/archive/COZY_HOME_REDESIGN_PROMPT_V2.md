## 提示词正文开始

你是 NativeMind 项目的资深产品设计师、插画视觉设计师和 React 前端工程师。你要重构一个已经存在、但视觉效果明显不合格的“心流小筑”主页面 Demo。

这次不是在旧页面上换几种颜色，也不是继续堆圆角卡片。你必须重新建立页面的视觉层级、空间感、角色质感和交互节奏，让它真正像一间可以安静待很久的 lo-fi 学习房间，同时保留番茄钟、任务、知识、复盘、陪伴和设置等未来功能入口。

这是一个面向学生和年轻职场人的桌面学习辅助软件，不是营销官网、儿童启蒙软件、后台管理系统，也不是游戏大厅。

最终气质必须是：

- 简洁、安静、温柔、可爱，但不幼稚。
- 日系绘本感与现代效率工具结合，但不模仿具体品牌或作品。
- 第一眼先看到“有人正在安静学习的房间”，第二眼看到计时器，第三眼才注意到功能入口。
- 装饰服务于陪伴感，不抢夺任务和计时信息。
- 用户可以长时间打开页面，不觉得刺眼、拥挤、吵闹或廉价。

### 1. 项目背景和架构边界

NativeMind 当前技术栈和运行关系如下：

```text
React + TypeScript UI
  -> Zustand UI store
  -> application use-case
  -> repository / AI port / infrastructure port
  -> Tauri runtime adapter
  -> Rust command
  -> SQLite / Ollama / file system / audio
```

浏览器预览还有本地 Demo runtime，用内存仓储和模板 AI 模拟真实能力。

本次任务只做独立视觉 Demo，必须完全绕开上述真实业务链。它可以有 React 本地状态和临时交互，但刷新后可以丢失，不能写数据库，不能调用模型，不能读写文件，不能调用 Tauri。

严禁在本次任务中：

- 修改 `src-tauri` 下的任何 Rust 文件。
- 修改数据库 migration、Repository、use-case、AI router、RAG 或模型 Provider。
- 调用 `invoke`、`@tauri-apps/api` 或任何 Rust command。
- import `src/ui/stores/runtime`、真实 Zustand store、application use-case、repository 或 infrastructure。
- 调用 Ollama、OpenAI、外部搜索、SQLite、sqlite-vec 或文件系统。
- 修改 `db_select`、`db_execute`、`model_is_ready`、`file_hash_content` 等现有契约。
- 删除或覆盖真实应用入口 `src/ui/App.tsx`。
- 为了 Demo 伪造“保存成功”“模型已回答”等会误导用户的结果。

本次允许：

- React 的 `useState`、`useEffect`、`useMemo`、`useRef`。
- 当前时间读取、CSS 动画和纯本地计时。
- 只存在于组件内存中的任务添加、勾选、面板切换、音乐播放视觉状态和宠物互动状态。
- 本地生成并提交到项目中的静态插画资源。
- 已有依赖。若项目没有统一图标库，可只新增 `lucide-react`，不要安装完整 UI 框架。

### 2. 现版必须解决的问题

不要保留现版的视觉错误。重构后必须逐项消除：

1. 当前页面像“一个大圆角房间卡 + 一个大圆角时钟卡 + 一排大圆角按钮”，缺少真实空间感。
2. 小女孩由圆形、矩形和胶囊形机械拼接，人体比例僵硬，像占位图，不像主视觉插画。
3. 桌面、窗户、角色、小物之间比例不统一，彼此像不同尺寸的贴纸。
4. 右侧时钟卡过重，把主场景压缩成左侧预览图，违背“主场景占大部分”的要求。
5. Dock 每项同时放图标、主标题和副标题，横向过宽，像后台导航，不够轻巧。
6. 页面圆角普遍达到 20 至 32px，产生廉价的“全员软糖化”，不符合项目 `--radius: 10px`。
7. 大量玻璃拟态、渐变和阴影叠加，没有明确光源，画面发灰发糊。
8. 暖米色、木色、绿色占比过高，缺少天空蓝、柔和珊瑚色等平衡色，整体发黄。
9. hover 将桌面物体上抬 7px，动作像可点击商品卡，不像安静房间里的小物。
10. 页面出现“Demo panel”“这里目前只是视觉 Demo”等说明性文字，破坏沉浸感。
11. 副面板内部继续套很多卡片，信息结构碎裂，像组件展览。
12. 音乐条、Dock、右侧时钟同时悬浮，底部和右侧视觉拥堵。

不要做小修小补。允许重写 `CozyHomeDemo.tsx` 和 `cozy-home-demo.css`，也允许拆分成若干仅供 Demo 使用的组件。

采用“柔和扁平插画 + 轻微纸张质感 + lo-fi 日系书房”的方向。


```text
赛博朋克
```

### 4. 设计 Token，必须统一使用

Demo 根节点可定义局部变量，但要与 `globals.css` 的变量语义兼容。颜色不能散落在几十个选择器中。

建议局部 Token：

```css
--home-bg: #f3f2ed;
--home-surface: #fcfbf7;
--home-wall: #e8e5dc;
--home-wall-cool: #dfe8e2;
--home-ink: #29332f;
--home-muted: #68716c;
--home-line: rgba(54, 67, 60, 0.14);
--home-green: #557762;
--home-green-soft: #dce8df;
--home-sky: #a9cfdd;
--home-sky-deep: #6e9cad;
--home-coral: #d88473;
--home-yellow: #e6bd73;
--home-wood: #aa704b;
--home-wood-dark: #77503b;
--home-shadow: rgba(42, 51, 46, 0.14);
--home-danger: #9c4a3f;
--home-radius: 10px;
--home-gap: 16px;
```

颜色比例：

- 35% 暖灰与纸白。
- 25% 天空蓝与冷灰绿。
- 20% 木色。
- 15% 深墨绿与文字色。
- 5% 珊瑚色或黄色点缀。

强强调色只用于当前主操作、计时进度和极少量插画细节，占页面面积不超过 10%。不要用紫色主渐变，不要用大面积橙棕色，也不要让整个页面只剩米色和绿色。

阴影只分三级：

```css
--shadow-soft: 0 8px 24px rgba(42, 51, 46, 0.08);
--shadow-float: 0 14px 36px rgba(42, 51, 46, 0.12);
--shadow-modal: 0 24px 64px rgba(31, 38, 34, 0.18);
```

同一元素只使用一个阴影。不要同时使用外阴影、内阴影、发光和 backdrop blur。

圆角规则：

- 普通按钮、输入框、内容面板：10px。
- 小标签：999px，但必须是真的标签或状态，不是普通按钮。
- 圆形计时器、头像、宠物身体可以是圆形。
- 主场景不放在 30px 大圆角卡片里；它应是页面本身。
- 底部抽屉上方圆角 16px 可以作为唯一结构例外。

边框统一为 1px，使用 `--home-line`。不要用 3px、4px 粗边框来画所有物件。

### 5. 字体和排版

不加载远程字体，使用系统中文字体栈：

```css
font-family: Inter, ui-sans-serif, system-ui, -apple-system,
  BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
```

字号固定，不使用随 viewport 缩放的字体，不用 `font-size: clamp(...vw...)`。

字号层级：

- 品牌名：15px / 600。
- 页面辅助信息：12px / 500。
- 当前本地时间：14px / 500，使用 tabular numbers。
- 主番茄数字：64px / 650，行高 1；小屏 48px。
- 副面板标题：22px / 650。
- 区域标题：15px / 600。
- 正文：14px / 400，行高 1.65。
- 次要文案：12px / 400，行高 1.5。
- 按钮文字：13px / 600。

所有 letter-spacing 为 0。不要用全大写英文眉题。页面可见文案以中文为主，lo-fi 曲名可保留英文。

不要在页面上写功能说明、设计说明、键盘快捷键说明或“这是 Demo”。这些属于代码文档，不属于界面。

### 6. 整体页面结构

桌面端以 1440 × 900 为主验收尺寸，同时支持 1280 × 720。

根布局必须占满 `100dvh`，页面不产生双滚动条。视觉从上到下分为：

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部安静状态栏：品牌 / 日期时间 / 场景控制                 56 │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│       窗外天空与房间                                         │
│                                                              │
│              小女孩写作业             专注时钟               │
│                                                              │
│  台灯   书本/杯子   笔记本   小绿团                           │
│════════════════ 木 色 桌 面 ═════════════════════════════════│
│                                                              │
│         底部 Dock                            lo-fi 音乐条      │
└──────────────────────────────────────────────────────────────┘
```

核心视觉比例：

- 主场景占首屏可用面积 75% 以上。
- 小女孩与书桌组合占主场景宽度约 42% 至 50%，不能只是一个小摆件。
- 计时器占主场景宽度约 18% 至 22%，与人物并列但不盖住人物。
- 窗户占上半部分宽度约 58% 至 66%，作为天空变化的主要载体。
- Dock 与音乐条合计不超过首屏面积 12%。

视觉层级固定为：

1. 小女孩 + 窗外场景。
2. 主番茄钟。
3. Dock 功能入口。
4. 小绿团和音乐条。
5. 品牌、日期、天气阶段等辅助信息。

### 7. 顶部状态栏

顶部栏高度 56px，左右安全边距桌面 28px，移动端 16px。不要做成悬浮玻璃卡。

左侧：

- 一个 24 × 24px 的简洁叶片或小屋标记。
- 文本“心流小筑”，15px、600。
- 不显示大型 `NativeMind` 英文 Logo。

中间不放内容，留白。

右侧：

- 当前日期，例如“8月3日 周一”。
- 一个小天气阶段图标：白天为 Sun，黄昏为 Sunset，夜晚为 Moon。
- 当前本地时间，例如“21:08”。
- 一个声音图标按钮，只改变本地视觉状态，不播放真实音频也可以。

所有工具图标使用统一的 18px 线性图标。优先使用 `lucide-react` 的 `Leaf`、`Sun`、`Sunset`、`Moon`、`Volume2`、`VolumeX`。图标按钮必须有 `aria-label` 和 tooltip，视觉尺寸 32 × 32px，点击热区至少 40 × 40px。

### 8. 主场景，不要再做“大卡片里的房间”

主场景直接铺在页面中，使用绝对定位分层，但必须有一个稳定的比例容器，避免不同窗口尺寸下物体漂移。

建议容器：

```css
.scene {
  position: relative;
  min-height: 0;
  height: calc(100dvh - 56px);
  overflow: hidden;
  isolation: isolate;
}
```

场景层级从后到前：

```text
z-index 0  房间底色与墙面轻纹理
z-index 1  窗外天空、太阳/月亮、星星、云、远山、飞鸟
z-index 2  窗框、窗帘、墙上软木板/置物架
z-index 3  地面或桌后暗面
z-index 4  小女孩主体
z-index 5  桌面和书本、台灯、杯子、盆栽
z-index 6  小绿团、计时器、音乐条
z-index 20 Dock
z-index 40 副面板遮罩
z-index 50 副面板
```

房间背景：

- 主墙面是偏冷的暖灰 `#e8e5dc`，不是黄色奶油色。
- 右侧可以有一块非常淡的灰绿色墙面，以色块区分计时区，不要画成卡片。
- 墙面纸张纹理使用极低对比度的 CSS repeating-linear-gradient 或伪元素噪点，opacity 不超过 0.04。
- 不允许使用装饰性渐变圆球、光斑、bokeh 或漂浮 orb。
- 只保留一个明确光源：窗外自然光 + 台灯暖光。

### 9. 窗外时间场景

使用本地时间自动确定阶段：

```ts
06:00 <= hour < 16:00 => day
16:00 <= hour < 19:00 => dusk
其余 => night
```

根节点使用 `data-sky="day|dusk|night"`，颜色和可见性由 CSS 控制。每 60 秒更新时间即可，不需要每帧 JS。

窗户构图：

- 位于场景左上至中上区域。
- 窗口本体宽约场景 62%，高约场景 42%。
- 窗框线宽 6px 至 8px，深木色，不能是 12px 以上的粗棕框。
- 窗框内分两到四格，但分隔条不要挡住太阳/月亮和主要山形。
- 窗帘只露出左右边缘，色彩为灰绿或灰蓝，不使用大褶皱动画。
- 窗台可放一只小玻璃瓶或两张便签，最多两个物件。

白天：

- 天空从 `#a9cfdd` 到 `#dce9e5` 的轻微纵向变化。
- 太阳位于右上 25%，直径 42px，边缘柔和但不做强发光。
- 两朵云，透明度 0.55 和 0.38，50 至 70 秒缓慢横移。
- 两层远山：后山灰蓝绿、前山灰绿，明度差不超过 15%。
- 只放 2 至 3 只飞鸟，轮廓很小，18 至 24 秒掠过一次。

黄昏：

- 天空使用低饱和珊瑚 `#d88473`、柔黄 `#e6bd73` 与灰蓝 `#7f91a5` 的纵向过渡。
- 太阳降低到地平线上方 18%，颜色变暖，透明度 0.82。
- 山体更深，房间整体覆盖一层不超过 0.08 的暖色光。
- 不使用紫红霓虹，不把整个页面染成橙色。

夜晚：

- 天空从 `#26364f` 到 `#526b78`，不要接近纯黑。
- 月亮为偏暖的灰白，直径 38px，可用遮罩形成弯月。
- 星星 14 至 18 颗，尺寸 1 至 3px，不等距排列。
- 星星只改变 opacity，不大幅缩放；闪烁周期 3.2 至 5.5 秒并错开。
- 房间墙面压暗约 8%，台灯暖光变得可见，但文字对比度仍达标。
- 不显示飞鸟；可改为一条极慢移动的薄云。

所有天空过渡使用 600 至 900ms 的颜色或 opacity 过渡，不做整页闪白。

### 10. 小女孩主视觉资产

这是画面主角，不能继续用简单圆形和胶囊形拼出廉价人体。

优先方案：创建一张项目内的透明背景 WebP 或 PNG 插画，放在例如：

```text
src/assets/cozy-home/study-girl.webp
```

要求：

- 由当前项目生成或原创，不引用不明来源图片，不使用远程 URL。
- 如果使用开源资产，必须确认允许商用并在 `src/assets/cozy-home/ATTRIBUTION.md` 记录来源和许可证。
- 透明背景，建议原始画布 900 × 900px 或更高，导出后文件尽量小于 600KB。
- 人物为侧前方三分之二视角，坐在桌前低头写字。
- 深棕色短发或低马尾，发丝是整洁的大形，不画密集动漫发丝。
- 穿灰绿色针织外套与米白内搭，可有小面积珊瑚色发夹。
- 表情平静，眼睛看向笔记本；不闭眼傻笑，不做夸张大眼。
- 身体姿势自然：肩线略向前，左手压住书页，右手持笔。
- 不幼态化，不使用校服、猫耳、夸张头身比，也不性感化。
- 绘画采用柔和扁平色块、轻微颗粒、少量边缘阴影；不要厚黑描边。
- 窗外冷光从左上照入，台灯暖光从左下或侧面照亮桌面，光向必须一致。

人物在 1440 × 900 下可视高度约 390 至 460px。头顶、手臂、笔记本必须完整，不要被桌面错误截断。人物和桌子接触处必须自然，不能像漂浮贴纸。

如果执行环境无法生成位图资产，可以使用分层 CSS/HTML 插画作为回退，但必须先满足：

- 头、躯干、手臂和桌面的透视关系正确。
- 不允许只用一个圆头、两个胶囊手臂和一个矩形身体。
- 至少拆分为头发后层、脸、刘海、耳朵、颈部、衣领、躯干、前后手臂、手掌、笔、笔记本和椅背。
- 肘部和手掌必须落在桌面同一透视面上。
- 用伪元素制造衣物褶皱与明暗，而不是用粗边框。
- 若回退结果仍像占位图，宁可使用简洁的半身剪影，也不要提交廉价娃娃造型。

人物动效非常轻：

- 整体 4.8 秒一次、上下 1.5px 的呼吸感。
- 持笔手 2.6 秒一次、旋转 1.2deg 的写字动作。
- 每 8 至 12 秒停笔 0.8 秒，随后继续。
- 不眨眼或最多 9 秒一次，避免所有角色同时眨眼。
- 动效只用 transform 和 opacity。

### 11. 木色桌面与小物

桌面是一条贯穿画面的横向结构，不是圆角卡片。

- 桌面位于场景高度约 66% 处。
- 桌板高度 22 至 28px，前挡板可见 110 至 150px。
- 木色主色 `#aa704b`，边缘和桌腿用 `#77503b`。
- 木纹只用 2 至 3 条低对比度长线，不用规则网格。
- 桌面投影方向与窗光一致。

桌面物件从左到右建议：

1. 台灯：位于左侧，灯罩简洁，黄铜或灰绿灯杆，光晕只覆盖笔记本区域。
2. 两本叠放的书：一本灰蓝、一本珊瑚，书脊有短线但无可读小字。
3. 打开的笔记本：位于人物双手下方，纸白，只有 3 至 4 条浅灰书写线。
4. 陶瓷杯：偏白或灰绿，带一条极淡蒸汽。
5. 盆栽：位于右后侧，三到五片叶子，不能比人物头大。
6. 小绿团：位于人物右侧、计时器下方或桌角，但不能挡住笔记本。

物件 hover：

- 只有真的可互动对象响应 hover。
- 最大位移 `translateY(-2px)`，最大旋转 1deg。
- 180ms ease-out。
- 台灯、书本等纯装饰不需要全部变成可点击商品。

咖啡蒸汽：

- 一到两条细线。
- 周期 3.2 秒。
- 位移不超过 8px。
- opacity 从 0 到 0.35 再到 0。

### 13. CSS 小绿团，必须纯代码实现

小宠物不使用图片、远程资源、Lottie 或 Rive。当前版本必须使用 HTML + CSS 完成，但代码结构要为未来替换保留接口。

尺寸：

- 桌面端可视身体约 82 × 72px。
- 移动端约 66 × 58px。
- 整个交互按钮点击区域至少 96 × 96px，视觉身体可小于点击区。

身体：

- 主色 `#79a97d`，底部略深 `#648f6a`。
- 轮廓接近软圆团，但底部稍平，使用不对称 border-radius，例如 `48% 52% 46% 44% / 56% 58% 42% 44%`。
- 顶部只保留很弱的亮面，不使用明显高光胶质渐变。
- 身体下方有 34 × 7px、opacity 0.12 的软阴影。
- 不画突出脚掌，避免像青蛙；底部可以有两个很轻的小凸起。

脸：

- 眼睛 5 × 8px，深墨绿，间距 22px。
- 嘴巴 12px 宽的浅弧线，线宽 1.5px。
- 腮红 10 × 5px，珊瑚色、opacity 0.30。
- 表情必须克制，默认安静，点击后才开心。

头顶芽：

- 茎高 18px，线宽 3px。
- 两片叶子约 13 × 8px，方向不完全对称。
- 叶子随呼吸轻微摆动，角度不超过 3deg。

idle 动画：

- 3.8 秒一个周期。
- 向上 2px、纵向 scale 1 到 1.018、横向 scale 1 到 0.992。
- 使用 ease-in-out。
- 阴影与身体反向变化，模拟落地感。

眨眼：

- 6.4 秒一个周期。
- 在 47% 至 49% 闭眼，然后立刻恢复。
- 第二只眼可错开 40ms，但不要变成频繁 wink。
- reduced motion 下不眨眼。

点击状态：

- 第一次 0 至 120ms：身体向下压缩到 `scale(1.06, 0.92)`。
- 120 至 280ms：向上弹 5px，恢复到 `scale(0.97, 1.05)`。
- 280 至 460ms：回到原位。
- 嘴巴变成更明显的弧线，眼睛可短暂弯起。
- 开心表情持续 1100ms 后回到 idle。
- 连续点击时清除旧 timeout，不能堆积动画。

气泡：

- 只在点击后出现，不要 hover 就自动出现。
- 位于宠物左上或右上，不能超出窗口，也不能盖住主计时数字。
- 宽 156 至 190px，padding 10px 12px，圆角 10px。
- 背景 `--home-surface`，1px 边框，轻阴影。
- 进入 180ms：opacity 0 到 1，translateY 5px 到 0。
- 停留 1800ms，退出 160ms。
- 气泡尾巴只做一个 8px 的小三角，不画厚边。

轮换台词，均不超过 30 个汉字：

```text
来了。今天想做点什么？
先挑一件小事就好。
我在旁边待着。
写一行，也算开始。
累了就慢一点。
先喝口水吧。
这段做完再歇一会儿。
```

状态接口：

```ts
type PetMood = 'idle' | 'greet' | 'happy' | 'concerned';
type PetAnimation = 'idle' | 'pop' | 'cheer';
```

在根元素保留：

```tsx
data-mood={mood}
data-animation={animation}
```

未来替换 Rive/Lottie 时，只替换宠物视觉节点，保留按钮语义、气泡、状态类型和点击处理。可在组件上方留一段不超过 5 行的注释说明该接入点，不要写长篇教程。

### 24. 动画总预算

动画要让页面有呼吸，不要让每个角落都在动。

同时持续运动的视觉对象最多六类：

1. 一层云。
2. 星星 opacity。
3. 小女孩的轻微写字。
4. 宠物呼吸。
5. 咖啡蒸汽。
6. 音乐均衡器，仅播放状态。

飞鸟不是永久循环，应间隔出现。Dock、面板等交互动画只在操作时发生，不计入持续动画。

性能要求：

- 持续动画只改 transform 和 opacity。
- 不在动画中改变 box-shadow、filter blur、width、height、top 或 left。
- 不使用 requestAnimationFrame 做纯装饰动画。
- 不为几十颗星星创建高频 JS 状态。
- `will-change` 只加在确实持续运动的少量元素上。

必须实现：

```css
@media (prefers-reduced-motion: reduce) {
  /* 停止所有装饰循环；保留必要的即时状态切换 */
}
```

reduced motion 下：云、飞鸟、星星、呼吸、蒸汽、均衡器停止；面板可用 80ms opacity 切换或无动画。

### 26. 可访问性和键盘交互

- 页面使用 `<main>`。
- Dock 使用 `<nav aria-label="功能入口">`。
- 顶部状态栏使用 `<header>`。
- 音乐条使用 `<aside aria-label="lo-fi 音乐">`。
- 宠物必须是 `<button type="button">`，不能给 `div` 加 click。
- 所有可点击图标有 `aria-label`。
- 所有焦点态使用 2px `--home-green` 外轮廓，offset 2px。
- 不用颜色作为唯一状态信号；active Dock 同时有状态线或字体粗细变化。
- 文本与背景达到 WCAG AA；正文至少 4.5:1，大字至少 3:1。
- 输入框必须有 label，可以使用视觉隐藏 label。
- 面板打开时管理焦点，关闭后恢复焦点。
- Tab 顺序与视觉顺序一致。
- `Esc` 只关闭当前副面板，不触发其他状态变化。

### 28. 本地 Demo 状态建议

所有状态只存在当前 Demo：

```ts

  | 'focus'
  | 'knowledge'

  | 'companion'
  | 'settings';
```
