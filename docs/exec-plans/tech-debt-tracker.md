### 编辑后检索与后台索引版本一致性（2026-11-11，本地源码，未发布）

- 先以真实临时 SQLite 复现 3 项失败：保存后仍搜出旧正文、新关键词无命中；复用旧哈希时也保留旧切片；向量生成过程中编辑后，旧结果仍写入并将新正文标 indexed。现新增迁移 032：正文或哈希变化时在同一保存事务内递增内部 content_revision、删除旧切片（FTS 同步失效）、清空索引派生状态。标题单独修改不删正文切片。普通搜索复用前两轮的当前正文回退，语义索引未完成不影响新正文关键词查找。
- ChunkNoteJob / EmbedChunksJob 读取正文与版本快照；切片替换和状态更新按版本条件提交。向量任务还核对切片 ID 集合，避免同一正文重新切片后的旧任务标记新切片完成；A→B→A 也不会复用旧版本。过期成功/失败结果不触发完成通知、不覆盖新状态；非空正文没有切片时不再误标 indexed。清空正文仍可正常完成清理。
- ParseNoteJob 接入取消与版本条件写入，只更新解析字段并保留并发标题/标签修改；解析期间用户编辑后，原文件结果不得覆盖已保存正文。修改过正文的文件笔记在重试时使用保存内容，不按已变化的阶段状态再次覆盖。未改变用户原文件。
- sqlite-vec 写入事务内验证切片仍存在且所属笔记/文本一致；查询前清理失去切片的派生向量，避免挤占 KNN 名额，查询结果再次从当前切片目录解析正文和位置。Chroma 在实际运行时装配同样的本地目录核对，过滤过期/悬空结果；其远端候选被过滤后可能少于请求数量，尚未加入扩大召回。两种通道都不将向量缓存文字当权威来源。
- 迁移只清理旧库明确标 stale 的切片，为缺少活跃任务的 stale 笔记补排 reindex；不重建全部健康索引、不更改笔记正文/链接/确认历史。磁盘升级、失败完整回滚、关闭重开与不重复执行通过。清理仅针对派生数据；尚不能自动识别历史版本已经错误标 indexed 的所有内容不一致记录。
- 新增 14 项回归，覆盖编辑后即时关键词/标题搜索、保存回滚、ABA、删除、切片/向量/原文件解析期间编辑、迟到失败、同版本重切、旧任务载荷、清空正文、当前版本成功完成与 Chroma 悬空结果。全套 1148 通过、4 项可选集成跳过；类型、ESLint、生产构建通过。额外显式运行真实 Anna 原生核心测试：2 通过、1 项打包启动器检查因未指定路径跳过，包含真实 vec0 的过期向量清理及进程重启；仅隔离临时数据库和合成数据，无真实模型调用。
- 仍待：生成回答期间用户再次改文后，对已取入内存的证据快照做最终版本复核；大库下查询前向量清理成本；全新电脑/Anna Agent 安装升级。已显示的历史回答不会被本轮自动重写。本轮未关闭用户软件、未替换安装包或发布 GitHub/Anna。

### 下一轮优先项核对（2026-11-11，分析，未修复）

> 此节记录修复前分析；正文/索引一致性已在上节实施，其他质量与规模问题仍待处理。

- **已复现的正文/索引不一致**：临时真实 SQLite 中先保存并切片“旧记录：提取率为百分之二十”，再按编辑后状态保存“更正记录：研究溶解度”并标 stale，不运行后台重建。正式候选提供器 + RetrievalStrategy（无向量）显示：完整标题预览仍是旧正文，已删除的“提取率”仍命中 1 条，新加入“溶解度”命中 0 条。上一轮只覆盖“没有任何切片”的新笔记，不能解决有旧切片的编辑笔记。诊断日志 output/search-freshness-diagnostic.log；临时诊断测试已移除，避免把断言旧错误行为的测试当作修复验收。
- **索引并发风险（代码检查，尚未并发实测）**：ChunkNoteJob / EmbedChunksJob 从旧快照生成切片/向量后，replaceChunks / updateIndexStatus 仅按 noteId 写入，没有正文哈希条件。下一轮应将内容版本贯穿任务、切片、向量与状态提交；过期任务不得标记新正文 indexed，检索不得将旧片段当当前证据。普通关键词检索应在重建期间读取当前正文，语义结果需过滤失效版本。
- **问答质量与延迟**：沿用 qa-isolated-pairs-2026-11-11.json 的真实验收结论：2 道正向正确、2 道正确拒答、6 道未解决，本轮未重新调用模型。当前先选证、再对每组证据串行两次核验，共用 20 秒截止；多调用同一模型不是独立验证。优先试验先摘录原文再写单一事实、对可验证事实保留并明确缺失部分，维持拒绝无据推断；固定题集 A/B，不靠增加超时或降低门槛提高“通过数”。

- **规模与交付**：标题查找目前需完整目录扫描，图谱仍扫描候选正文解析引用、预览限 1000 节点/10000 关系。先以合成大库测延迟/读取量再决定持久化标题/引用索引；不能把静态布局已实现误写成图谱仍无布局。安装版及线上 v2.0.1 不含随后两轮本地搜索修复，全新电脑与 Anna Agent 更新/失败恢复验收仍待环境。本轮不修改业务逻辑、不发布。

### 逐条隔离的证据复核（2026-11-11，源码候选，尚未发布）

- 上轮发现同一请求中的多组结论/引用可能互相补充语义，原文只支持部分事实也被放行。现在每次只给模型一组结论与原文；先执行原有布尔检查，再以 qa-evidence-check.v2 明确检查缺少的事实，两个检查都接受才保留证据。两种检查使用同一个本地模型，不构成独立来源验证，也不能保证消除误判。
- 新格式只输出短的缺失事实和 supported/partial/unsupported，不输出推理过程。不完整的因果、比较、范围或数量不应凭相关主题放行；即使 verdict=supported，只要 missing 非空仍拒绝。第一步判否就停止该配对检查；格式无效、服务失败或超时明确属于“核验未完成”。所有配对及两种检查共享原有 20 秒核验截止，仍最多修正一次，不重试无效响应、不切换云端。
- 先固定上一轮原文/结论做对照，再接正式流程。12 组固定配对（8 组真实输出、4 组合成对照）中，旧单条检查 9/12、新检查单独使用 9/12，组合检查 10/12。新检查单用会误放行一条标题证据，因此未直接替换旧检查；组合检查拦截了旧检查漏掉的额外“循环结构”因果解释。仍有 1 组局部因果被误放行、1 组与人工正向预期不符；其中后一组含依赖上下文的指代，应继续保留为争议用例，不能为提高分数事后修改答案。不能把该小样本提升当作通用准确率。
- 可重复运行的本地模型对照：`scripts/benchmark-pair-verifier.mjs <上轮 pipeline-acceptance.json>`。保留旧 qa-evidence-check.v1，新增 v2，不覆盖旧协议。完整书籍与模型输入仍只存在隔离临时目录。
