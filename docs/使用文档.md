# NativeMind 使用与实现文档

> 本地优先的 AI 学习节律工具。本文覆盖：功能怎么用、每个功能背后的实现流程、功能之间如何调用。
> 版本：v0.1.0（MVP）

---

## 1. 项目是什么

不是聊天机器人，而是四件事：把今天要学的东西变清楚、把专注过程记下来、把新旧知识自动关联、把学习结果沉淀成本地复盘。

**核心原则**：AI 只在用户需要时出现；所有写入需用户确认（AI 建议只是草稿）；数据留在本机；RAG 是"学习连接器"不是问答机器。

**技术栈**：Tauri v2（Rust 后端 + 轻量 WebView）+ React 19 + TypeScript + Zustand + SQLite + sqlite-vec（向量）+ Ollama（本地模型）。

---

## 2. 快速开始

```bash
npm install            # 前端依赖
npm run tauri dev      # 桌面开发模式（推荐）
# 或 npm run dev       # 纯浏览器预览（内存驱动，数据不持久化）
```

前置：本机装好 **Ollama**，并至少拉取两个模型（默认 `qwen2.5:1.5b` 小模型、`qwen2.5:14b` 大模型）与一个 embedding 模型（`nomic-embed-text`）。模型名可在 设置 → 模型 里改，并可用「检查模型可用性」按钮验证。

数据位置（Windows）：`%APPDATA%\com.nativemind.app\`（`nativemind.db` 数据库、`imports/` 导入副本、`backups/` 每日备份、`extensions/` 向量扩展）。

## 3. 功能清单与使用

| 页面 | 功能 | 一句话 |
|---|---|---|
| 今天 | 任务管理 + AI 拆解 | 加一条任务，AI 自动拆成可执行子任务 |
| 专注 | 番茄钟 + 环境音 + 音乐 | 开始专注、呼吸计时、可选环境音与本地音乐 |
| 知识 | 笔记导入/检索/查看/删除/关联 | 本地知识库，向量 + 关键词混合检索 |
| 连接 | 知识图谱 | 笔记间关系可视化 |
| 提问 | 苏格拉底式对话 | 基于笔记的引导式提问 |
| 复盘 | 日/周/月复盘 | AI 生成复盘，可重新生成（需确认） |
| 陪伴 | 宠物 + 陪伴 agent | 一只会主动关心你的小宠物 |
| 设置 | 路径/模型/搜索/隐私 | 所有配置本地持久化 |

### 3.1 今天（Todo + AI 拆解）

**用法**：在"加一条"输入目标 → 回车 → AI 自动拆成多条草稿 → 选「采用拆分」（多条、带"同组"标记）或「直接加入」（单条）。今日页只显示待办与当天完成的；历史任务保留供复盘统计。

**流程**：
```
输入目标 → todo-store.structureGoal → CreateTodoUseCase.structureGoal
  → TodoStructuringAdapter → ModelRouter(todo_breakdown, coach=大模型)
  → prompt todo-structuring.v1 → JSON 草稿数组 → 页面预览
用户选「采用拆分」→ executeDrafts(共享 sourceGoalId 软连接, 无外键)
用户选「直接加入」→ execute(单条)
→ TodoConfirmed 事件 → App 刷新列表
```

**细节**：
- 拆解走 `todo_breakdown`（大模型，理解语义）；结构化转严格 JSON 走 `todo_structuring`（小模型）。
- 拆分出的多条任务共享同一个 `sourceGoalId`（DB `source_goal_id` 列），表示"同一目标的整体"，是软连接不是外键。
- AI 拆失败（模型不可用/格式错）→ 明确报错并引导"直接加入"，不让录入卡住。
- 任务不物理删除：今日页视图只显示"待办 + 当天完成"，历史保留供复盘统计。

#### 每日打卡（单日进度 + 打卡日历）

今日页右栏有「**今日打卡**」卡片与「**打卡日历**」：

- **任务进度**：今日任务（当日排期或当日新建）每完成一个加一段进度；全部完成 → 「**今日已学习 ✅**」＝ 当天打卡成功。
- **学习进度**：当日专注分钟 / 目标（设置 → 专注 →「每日学习目标」，默认 50 分钟，可配 30/50/90/120），进度条随专注累积。
- **打卡日历**：月视图，成功日打勾（今天高亮描边），可翻月；数据来自 `daily_checkins`（`012` 迁移），任务完成 / 专注完成 / 任务增删改时由订阅者重算落库 —— 这也是**后续学习效率分析**的每日结构化数据源（`tasks_total / tasks_completed / focus_minutes / study_goal_minutes / check_in_done`）。

### 3.2 专注（番茄钟）

**用法**：主页「专注」栏已入口化——**不再展示大计时器**（番茄钟 UI 骨架保留，时钟后续由 AI 生成），只保留一个「**进入专注模式**」按钮 + 今日/本周统计；主页**右侧悬浮的 Focus HUD 也精简成小按钮 + 「今天 X 分钟」**，去掉大圆环计时器。计时发生在全屏专注层（点按钮进入，或**今日 todo 里点任务的「开始」直接进全屏**）。全屏内选时长（15/25/45/60）+ 关联任务 → 开始 → 大计时器；到点不自动判完成，提示"收个尾再点完成"；点「完成这段」后**直接退出全屏**。**按 ESC 或点 X 退出**：正在专注中会先弹确认（需点击才退出），空闲直接退。全屏右下角有**音量/静音**（与主页同步，控制全局声音——环境音/音乐/专注音乐都响应）与专注音乐开关；专注音乐在放时不叠加环境音。**「专注时保持安静」（设置 → 专注）默认开启**：专注中停掉环境音/音乐只留专注音乐；关掉后环境音继续放，音量键即可控制全局声音。专注中隐藏多余入口，只留计时 + 放弃。完成一段后自动进入**休息倒计时**（时长在设置里配，默认 5 分钟），可「跳过休息」。今日/本周统计来自持久化 `focus_sessions`，按实际专注分钟计。

**流程**：
```
开始 → focus-store.start → StartFocusUseCase → focusPolicy.activate(会话)
  → FocusTimer 渲染倒计时（呼吸动画）
到点 → onElapsed 提示 → 用户点完成 → CompleteFocusUseCase
  → 记录 focus_sessions + 发 FocusSessionCompleted 事件
  → 陪伴订阅者触发 focus_complete；可选播 completionCue 提示音
  → 进入休息倒计时（focus.breakDurationMinutes）
```

**细节**：
- **低打扰**：专注中 `FocusModePolicy.isActive()` 为真，AI 主动行为、外部搜索、陪伴提问、后台重任务（embedding）全部被政策拦截。
- **同一时刻只响一个**：环境音 / 音乐库 / 专注音乐 / 自定义天气歌四路音源互斥（`audio-exclusive`），任一播放会停掉其余，保证不叠音；音量键控制全局。
- 重启后策略恢复：启动时查 `findActive()`，若有活动会话就重新 `activate`，保证"专注中安静"不破防。
- **统计持久化**：今日 / 本周分钟由 `focus-store` 的 `selectTodayFocusMinutes` / `selectWeekFocusMinutes` 从 `focus_sessions` 现算（本周从周一起算），历史数据落 SQLite，重启不丢；统计用 `actualMinutes`（提前结束按真实时长），老数据缺省回退计划值。

### 3.3 知识库（导入 / RAG / 查看 / 删除 / 关联）

**用法**：知识面板分三栏——「**检索**」（搜索 + 深度回答 + 问答历史）、「**笔记整理**」（按月/日分组的时间线 + 全部笔记列表，可查看/删除/归纳）、「**快速导入**」（粘贴文本或选文件）。支持 Markdown / txt / PDF / EPUB / MOBI / AZW3，导入自动复制进数据目录、后台切块建索引。

#### 导入流程
```
知识页选文件 → Rust file_import_into_data_dir（已在许可目录内则原路径，否则复制进 data_dir/imports/）
  → importNote → ImportNoteUseCase
  → FileImportService.parse（按扩展名分派：pdf→Rust pdf-extract；epub/mobi/azw3→Rust lib-epub/mobi+html2text；md→markdown-parser；txt→text）
  → 内容 SHA-256 哈希去重（同内容返回已存在笔记）
  → 保存 note(indexStatus=pending) → NoteImported 事件
```

#### RAG 索引流程（后台任务队列）
```
NoteImported → 入队 parse_note（带 noteId，按篇处理）
parse_note：有源文件则重解析（哈希没变跳过）→ 入队 chunk_note
chunk_note：chunkText 切块 → replaceChunks(本笔记) + vectorStore.deleteByNote(本笔记) → 入队 embed_chunks
embed_chunks：Ollama(nomic-embed-text, 768维) 分批向量化 → sqlite-vec upsert → 标 indexed
```

**检索增强（RAG）**：
- **混合检索**：向量 + 关键词/标签两层召回合并，按分排序。
- **多查询/子查询**：默认启发式改写查询（拆并列连词 + 关键词变体）；知识面板开「**深度检索**」后用本地模型做 Multi-Query + HyDE（慢但更准）。
- **父子块**：同一章节多个子块命中时合并返回完整章节（上限 2000 字，**每 2 段一组**）——整篇挂同一标题的大文档按段出结果，不会并成整篇一个命中，用户能定位到具体哪一段。
- **重排**：深度检索可用模型重排（生成式 LLM 打分 / 可选**专用 cross-encoder**，本地 llama-server 跑 bge-reranker 类模型的 `/rerank` 端点），失败回退启发式。
- **多笔记轮询**：最终结果按**笔记轮询**（每篇最多 3 段）——多篇命中笔记的段落都会出现，不会被高分单篇挤掉；每条命中标注所属**笔记标题 + 章节路径**。
- **结果展示**：每条命中显示所属笔记标题 + 章节面包屑，点击查看完整笔记。
- **时间线**：知识面板可切「时间线」视图，按月/按日分组，每月可「归纳本月」生成小结（桌面端调本地模型）。
- **深度问答（Self-RAG）**：搜索框旁「深度回答」按钮 → 深度检索取相关片段 → 本地模型生成草稿 → 自我评判（相关性 / 有据 / 幻觉风险 / 质量，`qa-critic.v1`）→ 不达标带评判意见重生成一次 → 返回「回答 + 引用来源 + 置信度」。生成过程**流式输出**逐字展示（Ollama NDJSON / llama.cpp SSE / 桌面端 Rust Channel）。低置信度提示对照引用核实。模型不可用降级为「最相关片段」。
- **问答历史**：每次非空问答自动落库 `ask_sessions`（`011` 迁移），知识面板「问答历史」区可回看（问题 + 回答摘要 + 置信度 + 时间）与删除。

**关键点**：
- **增量**：每次只处理这一篇，`replaceChunks`/`deleteByNote` 只清这篇的旧数据，不整库重建。
- **去重**：内容哈希相同直接返回已存在笔记。
- **断点续传**：任务队列落库（`background_jobs` 表），重启后 `recoverStaleJobs` 续跑，不是整份重来。
- **切块策略**（`chunk-strategy`）：Markdown 按标题层级切（保留 headingPath 便于回溯）；PDF/文本按段落聚到目标 800 字、上限 1500、下限 200。
- **降级**：sqlite-vec 不可用 → 关键词检索（FTS5，失败再退 LIKE）；embedding 模型不可用 → 笔记仍可用但无向量。

#### 检索流程
```
搜索 → SearchNotesUseCase → 本地检索（RAGOrchestrator）
  → 候选：向量 KNN + 关键词（FTS5/LIKE）
  → 打分：向量相似度 + 关键词命中 + 标签重叠 + 关系规则
  → 本地结果不足(<3)且允许联网 → 外部搜索补充（见 3.5）
```

#### 查看/删除/关联
- 查看：弹窗内**只读 textarea**（大文件不铺满 DOM）+ PDF 显示「第 N 页 / 共 M 页」（`pageRanges` 随导入存进笔记 metadata）。
- 删除：`DeleteNoteUseCase` → 事务删正文+chunk → 清理该篇向量。
- 关联：`suggestForNote` → RAG 找相似旧笔记 → 关系判断（大模型）→ 建议经确认后写入 `knowledge_links`。导入后自动触发，有建议会弹确认框。

### 3.4 连接（知识图谱）

基于 `knowledge_links`（双向边）用 D3 力导向图渲染。节点标签按类型取笔记/任务标题，缺失实体降级为"类型+短id"。归档（archive）而不是硬删，便于撤销。

### 3.5 提问（苏格拉底）

选一篇相关笔记 → `SocraticSession`（多轮，保留最近 6 轮历史）→ 大模型基于笔记 + RAG 上下文提问/反馈。专注中禁止开启。

### 3.6 复盘（日/周/月）

**用法**：复盘页点「今日/本周/本月复盘」→ 确认草稿后落库。可反复点击重新生成（覆盖）。历史复盘可删除。AI 生成的复盘一律经确认门，无后台静默写入。

**流程**：
```
点生成 → review-store → GenerateDaily/Weekly/MonthlyReviewUseCase
  → 聚合日期窗口内 todos + focus_sessions（日=1天 / 周=7天 / 月=30天）
  → ReviewGeneratorPort.generate → ModelRouter(review_daily→coach, weekly/monthly→deep)
  → prompt review-daily.v1 → ReviewDraft(内容/摘要/洞察/下一步)
  → confirmAndCommit（用户确认）→ save（按 review_type+date UPSERT 覆盖）
  → ReviewGenerated 事件

```

**细节**：重新生成即覆盖（UPSERT 以 `(review_type, date)` 为键）；删除走确认。

### 3.7 陪伴（宠物 + agent）

**用法**：宠物会随事件说话（进入/专注完成/卡住/复盘生成），也会**主动关心你**（陪伴 agent：空闲久了、有卡住的任务、达到里程碑时主动说一句）。点它/回复它会有回应。专注中绝不主动打扰。

**像素咕咕嘎嘎**：宠物视觉为像素风（低饱和鸭黄 + 橘橙喙 + 方形像素边）；**可鼠标拖拽到任意位置**（pointer 捕获，松开停住；未拖拽时按场景锚点）。精确形象可用 Sprite Sheet 替换（`companion.assetBase` 下放 `pet-manifest.json` + 角色帧，见桌宠接入文档）。

**背景视频音效**：晴·白天背景为 `白天.mp4`（循环播放、自带音效）；音效**跟随主音量键**。三条静音规则：① 用户播放任何音乐 → 自动静音，音乐全停恢复；② **进入专注模式 → 静音**；③ 全部停下后恢复（走 `audio-exclusive` 活跃音源互斥）。

**流程（主动 agent）**：
```
App 每 10 分钟 → companion-store.proactiveTick → ProactiveCompanionTickUseCase
  → 聚合上下文：今天专注分钟/完成任务数/pending 数/卡住天数/距上次互动
  → decide(companion-agent)：规则决策（卡住>鼓励 / 里程碑>肯定 / 空闲久且有活动>轻招呼 / 否则安静）
  → InteractionPolicy.allowProactiveInitiation（专注中否 / 距上次≥30分钟 / 每场景每日≤3次）
  → InteractionGenerator.generateDialogue（companion_dialogue，fast=小模型 1.5B，≤30字，超长回退模板）
  → 写 companion_interactions → 显示气泡+动画+音效
```

**状态 → UI**：idle(待着) / greet(招呼) / cheer(专注完成) / question(提问带输入框) / concerned(卡住鼓励)。台词短、不打鸡血、不吵。

### 3.8 设置

| 分组 | 内容 |
|---|---|
| 模型 | 大/小模型名（Ollama）+「检查模型可用性」 |
| 路径 | 数据目录（可改，热替换无需重启）+ 资源目录（可改，即时生效）+ 可读目录（浏览/手动，导入用）+ 音乐目录 |
| 专注 | 默认时长、休息时长、每日学习目标、完成提示音、专注背景音乐 |
| 搜索 | 搜索引擎（Bing 默认 / Google Custom Search API 可选，需 key+CX） |
| 隐私 | 允许外部搜索（**默认开启**）、每次联网确认 |
| 陪伴 | 开关、显示名、形象资源路径 |
| 界面语言 | 中文 / English（模型回信语言与写信功能也跟随此设置） |

所有改动即时落库（settings 表 key/value），重启保留。

**界面语言**：设置 → 模型与外观 →「界面语言」可切中/英。中文为源语言，英文由 i18n 覆盖表（`src/ui/i18n/en.ts`）提供；已翻译面板（今日 / 写信 / 专注入口 / 全屏专注 / 功能栏）切语言即时生效，未翻译面板暂时回退中文（翻译持续补齐中）。

### 3.9 写信（Flora）

底部功能栏新增「**写信**」栏，笔友 ID：**Flora**。

**agent 链**（`src/ai/flora/flora-agent.ts`）：
```
来信 → letter_emotion（fast=低级模型）：通读全信，输出情绪 / 摘要 / 建议语气（JSON）
     → letter_reply（deep=高级模型）：按设置语言写回信（自由文本）
     → letter_verify（fast=低级模型）：校验语气贴合 / 回应了内容 / 用了目标语言（JSON）
       → 不达标带意见重生成一次 → 再校验
```

**细节**：
- **实时回信 + 信封 UI**：写信后立即回信（`letters` 表，`013` 迁移，`014` 加 `direction` 字段）；面板**双栏**——左「寄出」（我的信）、右「收到」（Flora 来信），每封信是**可点击信封**（`Mail` 图标 + 日期），点开看内容。
- **回信固定以「dear love」开头**，末尾由程序追加**实时日期**落款（中文 `2026年8月5日`，英文按地区格式）。
- **主动来信**（`GenerateIncomingLetterUseCase`）：**每月一次学习鼓励信**（`letter.lastEncourageMonth` 跨月才发）；**每日一次 30% 抽签**（`letter.lastDrawDate` 当天只抽一次）抽中按类型出信——`encourage` 学习鼓励 / `whats_up` Flora 近况（**调网络搜索**引用一条近期见闻）/ `warm` 温暖鼓励；内容按**设置语言**（中/英）输出。信封标签显示类型。
- **兼容修复**：`letters` 仓库加**防御性补列**（老库缺 `direction`/`type` 列时自动 ALTER 补上，自愈「no column named direction」错误）；迁移 `014`(direction)、`015`(type)。
- 模型不可用才留 pending（`ProcessLettersUseCase` 自动补发，早期版本遗留的排队信也会被补上）。
- 回信语言跟随设置「界面语言」：中文模式用中文回，英文模式用英文回。
- 每步失败降级：情感分析失败则不带分析直接回信；回信失败提示模型不可用；验证失败接受当前回信。

**路径可改**：存储地址/资源目录可在设置里改，**即时热替换无需重启**。数据目录改动会连同数据库/导入/备份一起迁移到新目录（覆盖值写在默认数据目录的 `paths.json`）并直接切换数据库连接，前端随后自动刷新。专注页另有独立的「专注背景音乐」配置（与天气环境音分开）。

**背景音乐按环境**：晴/雨/雪/春/夏每个环境可选内置/无/自定义，模式和自定义文件都持久化到 settings 表，重启不丢；右下角音乐条会显示正在播放的自定义歌曲。

**场景背景图**：场景与女孩已融入 `src/ui/background/*` 背景（晴/雨/雪各白天+夜晚两版，春=樱花、夏=萤火虫各一张；**晴·白天已用 `白天.mp4` 视频**），顶部天气按钮与设置里可切 5 种天气、白天/夜晚；背景按 `(weather, timePhase)` 映射并 crossfade 切换（后续图片逐步替换为视频，`backgrounds.ts` 改 src 即可）。CSS 手绘场景/女孩/雨雪粒子已移除，只保留宠物与功能 UI。

**像素风 · 莫兰迪低饱和主题**：功能 UI（HUD/Dock/面板/按钮/卡片）像素化——方角 + 2px 硬边 + 像素硬阴影；全局饱和度锁 20-30%、≤4 主色。白天：米白 + 浅橡木 + 灰绿点缀；夜间：炭灰蓝底 + **台灯暖光为唯一亮色**（`data-hud='dark'` 时 accent 变暖琥珀）。

## 4. 核心机制详解

### 4.1 RAG 全链路

```
┌ 导入 ─────────────────────────────────────────────────┐
│ 文件 → Rust 解析 → 纯文本 → 去重 → note                │
└────────────────────────────────────────────────────────┘
        ↓ NoteImported 事件
┌ 后台任务队列（background_jobs 表，可断点续传）─────────┐
│ parse_note → chunk_note → embed_chunks                │
│ 切块(heading path) → 向量化(768) → sqlite-vec          │
└────────────────────────────────────────────────────────┘
        ↓ 检索时
┌ 检索 ─────────────────────────────────────────────────┐
│ 查询 → 向量 KNN + 关键词(FTS5) 候选 → 打分 → 结果      │
│ 向量库不可用 → FTS5 → 再退 LIKE                        │
└────────────────────────────────────────────────────────┘
```

**为什么按篇**：chunk/embed 都是针对单篇 noteId 的后台任务，旧数据只清这一篇，保证"加一篇笔记"不触发整库重建。

### 4.2 写入确认门（Confirmation Gate）

- **AI 建议型写入**（拆任务、建知识链接、复盘草稿、导入搜索结果）→ `ActionProposal` → `ConfirmationService.confirmAndCommit` → 用户确认 → 落库。
- **用户手动操作**（打字加任务、完成、删除）→ 用户动作本身就是确认，直接写库，不二次弹窗。
- 确认弹窗全局统一（`ConfirmationModal`）。

### 4.3 事件系统（EventBus）

写入方发事件，订阅者统一刷新，避免各 store 手动 refresh。主要事件：`TodoConfirmed / TodoCompleted / FocusSessionCompleted / NoteImported / NoteIndexed / ReviewGenerated / KnowledgeLinkConfirmed / CompanionInteractionCompleted / AppEntered` 等。

### 4.4 模型路由（本地 + DeepSeek 双引擎）

| 层 | 默认模型 | 任务 |
|---|---|---|
| fast | 本地小模型 `qwen2.5:1.5b` | 意图识别、Todo 结构化、检索词生成、结果过滤、陪伴对话、轻量摘要 |
| coach | 本地大模型（14b）或 DeepSeek 云端 | 目标拆解、苏格拉底提问、知识关系判断、**每日复盘**、结果排序 |
| deep | 本地大模型（14b）或 DeepSeek 云端 | **每周/每月复盘**、长文档分析 |

- 模型名由 `model-config` 单例解析（fast→小，coach/deep→大），设置里改**无需重启**。
- **DeepSeek 可选**：设置 → 模型 填入 API key 并「保存并启用」后，coach/deep 走云端
  （`deepseek-v4-flash` 快 / `deepseek-v4-pro` 强，可开思考模式）。本地小模型不可用时
  fast 自动兜底云端。key 未配或切回本地 → 全部走本地。
- 降级链：fast 失败升 coach；coach/deep 失败退 fast；全失败 → 调用方转人工/模板。
- **数据说明**：启用 DeepSeek 后相关请求（笔记内容/任务/复盘上下文）会发送到其服务器，
  设置页有明确提示；未配置则一切留在本机。

### 4.5 外部搜索

本地结果不足且允许联网时触发。引擎由 `search-config` 单例提供（设置切换即时生效）：默认 **Bing**（抓取 HTML，实测可解析，无需配置）；可选 **Google Custom Search API**（官方接口稳定无反爬，需在设置填入 API key + 搜索引擎 ID CX，免费 100 次/天）。Rust `search_fetch` 抓取/请求，前端解析成结果，再经过滤/排序。只发关键词，不发笔记原文。

### 4.6 数据、备份与清理

- **备份**：每日维护调度执行 `db_backup`（Rust `VACUUM INTO` 一致性快照 → `backups/nativemind.db.bak`，覆盖保留一份）。
- **清理**（每日）：过期后台任务(7天)、过期陪伴记录(90天)、过期建议(24h)、旧模型调用日志(30天)、本地日之前完成的旧任务。
- **路径安全**：读只放行 `data_dir / resource_dir / 设置的读取目录`；写只落 `data_dir`；导入任意路径文件会先复制进 `data_dir/imports/`。

## 5. 功能之间的调用关系

```
Today(拆任务) ──TodoConfirmed──► 列表刷新；可点「专注」跳转 Focus
Focus ──FocusSessionCompleted──► Review 数据源 / Companion(focus_complete) / 复盘自动建议
Knowledge(导入) ──NoteImported──► 后台索引；NoteIndexed 后检索可用
Knowledge ──suggestForNote──► KnowledgeLink(连接页图谱)
Review ──ReviewGenerated──► Companion(review_generated)
Companion ──阅读 todos/focus──► 决定主动说什么
Settings ──models/search/paths──► 模型路由 / 搜索 / 文件许可（即时生效）
```

**数据流总览**：
- 写入：UI → store → 用例 →（AI 建议走确认门）→ 仓储 → SQLite → 事件 → 订阅者刷新。
- AI：用例 → AI 端口 → 适配器 → ModelRouter → 模型运行时(Ollama) → 结构化输出校验 → 返回用例。

## 6. 常见问题排查

| 现象 | 检查 |
|---|---|
| RAG 搜不到向量结果 | 设置 → 检查 sqlite-vec（`vector_status`）；确认 embedding 模型 nomic-embed-text 已装 |
| AI 任务没反应 | 设置 → 模型可用性检查；确认 Ollama 已启动、模型名对 |
| 外部搜索无结果 | 确认引擎配置：Bing 无需配置；Google 需填 API key + CX；检查「允许外部搜索」开关 |
| 导入报"路径超出范围" | 已由复制进 data_dir 解决；老版本需重启 |
| 复盘没生成 | 手动点生成；AI 建议需确认后才落库 |
| 数据丢了 | `backups/nativemind.db.bak` 是最近一份快照 |
