# NativeMind 功能总览

> 本地优先的 AI 学习节律工具：把「今天要学什么」变清楚、把专注过程记下来、把新旧知识自动关联、把学习结果沉淀成本地复盘。
> 本文档按功能逐一说明「对应哪个 UI → 做什么 → 实现在哪里（文件路径）」，覆盖主界面 HUD、功能面板、宠物、场景背景、AI/agent 层、笔记检索链路与数据层。
> 实现以代码为准，本文档与 `docs/使用文档.md`、`docs/ARCHITECTURE.md` 互相补充。所有路径均为项目根目录下的相对路径。

---

## 1. 项目总览

| 项 | 内容 |
|---|---|
| 定位 | 本地优先的 AI 学习节律工具（不是聊天机器人） |
| 技术栈 | Tauri v2（Rust 后端 + WebView）+ React 19 + TypeScript + Zustand + SQLite + sqlite-vec + Ollama |
| 核心原则 | AI 只在需要时出现；AI 建议型写入必须经确认门；数据留在本机；RAG 是「学习连接器」不是问答机器 |
| 分层 | `domain`（纯逻辑）→ `application`（用例/端口/事件/策略）→ `infrastructure` + `ai`（实现）→ `ui` |
| 运行形态 | `npm run dev`（浏览器预览，内存运行时、不持久化）/ `npm run desktop`（Tauri 桌面，SQLite + 本地模型） |

**入口**：`src/main.tsx` → `src/ui/demo/fullscreen-cozy-home/FullscreenCozyHome.tsx`。旧的 `src/ui/pages/*`、`src/ui/App.tsx` 已删除。

**运行时装配**（决定浏览器/Tauri 两套实现）：
- `src/ui/stores/runtime.ts` —— 运行时单例，按 `window.__TAURI_INTERNALS__` 检测环境，导出 `useCases / policies / eventBus / repositories / infrastructure / audioPlayer / ai / aiMode`。
- `src/infrastructure/tauri-runtime.ts` —— 生产装配：SQLite 仓储 + 真实 AI 层（`aiMode: 'model'`）。
- `src/infrastructure/local-demo.ts` —— 浏览器内存仓储 + 模板 AI（`aiMode: 'template'`）。
- `src/application/bootstrap.ts` —— 应用层装配：注入仓储/AI 端口，构建全部 use-case 并注册事件订阅者。

**UI 写库铁律**：UI 组件 → Zustand store → application use-case → repository → SQLite；AI 建议型写入（拆任务、建知识链接、复盘草稿、导入搜索结果）一律走 `ConfirmationService.confirmAndCommit` 确认门，用户确认才落库。

## 2. 主界面 HUD（全屏「心流小筑」）

主界面是单页全屏场景：`FullscreenCozyHome.tsx` 渲染场景画布 + 若干 HUD 层。各 HUD 是场景的兄弟节点（z20+），组件都在 `src/ui/demo/fullscreen-cozy-home/components/`。

| HUD | 组件文件 | 功能 |
|---|---|---|
| 顶部栏 | `components/TopHud.tsx` | 品牌 logo、场景/天气切换、时段循环、日期时间、音量 |
| 功能收纳按钮 | `components/FeatureDock.tsx` | 右下角单一圆形按钮，展开 7 个功能入口 |
| 专注入口 + 统计 | `components/FocusHud.tsx` | 右侧悬浮「进入专注模式」按钮 + 今日专注分钟 |
| 音乐栏 | `components/LofiHud.tsx` | 右下角 lo-fi 播放条：上/下一首、播放暂停、曲目列表、顺序/随机 |
| 气泡 | `components/SpeechBubble.tsx` | 宠物气泡，锚定在宠物上方、跟随拖动 |
| 等待转圈 | `components/PetActor.tsx`（`pet-spinner`） | 调本地模型生成回应时宠物右上角转圈 |
| 场景画布 | `components/SceneViewport.tsx` | 背景图/视频 + 时间光照 + 宠物 + 压暗层 |

### 2.1 顶部栏 TopHud

- **做什么**：左侧品牌区（logo `src/ui/components/ui/logo.png` + 「NativeMind」+ 场景名）；右侧按信息优先级排布——场景切换（房间/图书馆 segmented）、天气切换（晴/雨/雪/春/夏 图标按钮，图书馆下隐藏）、固定时段切换按钮（点击循环 白天→黄昏→夜晚）、日期、时间、音量。
- **时段循环**：`onToggleDayNight` 在 `FullscreenCozyHome.tsx` 里定义，`['day','dusk','night']` 循环，非 auto 模式下手动固定；auto 模式由本地时间推导（`phaseForHour`，`utils.ts`）。
- **音量交互**：单击音量图标打开滑杆面板；双击音量图标整体静音。音量/静音状态是 `FullscreenCozyHome` 的本地 state，作用到四路音源（见 2.6）。
- **场景/天气切换**：只是视觉偏好，写进 localStorage（key `nativemind.demo-settings.v1`），不落 SQLite。
- **依赖**：i18n `src/ui/i18n/index.ts`（`useT`）。

### 2.2 功能收纳按钮 FeatureDock

- **做什么**：主界面只留一个圆形「功能」按钮，点击展开/收起 7 个功能项：今天、专注、知识/检索、复盘、陪伴、对话（写信）、设置。点外部或 Esc 自动收回；点某项打开对应面板并收回。
- **面板打开逻辑**：`openPanel` 在 `FullscreenCozyHome.tsx`：`focus` 直接打开全屏专注层（`useFocusOverlayStore.openOverlay`），其余打开底部副面板 `DemoSheet`。
- **副面板容器**：`components/DemoSheet.tsx` —— 7 个面板常驻挂载、用 `hidden` 切换显示（关闭后本地草稿状态保留），含焦点管理与 Tab 循环、关闭确认。

### 2.3 专注入口 + 统计 FocusHud

- **做什么**：右侧悬浮紧凑版。只保留「进入专注模式」按钮 + 「今天 X 分钟」统计，不再展示大番茄钟圆环（计时发生在全屏专注层）。专注进行中显示「专注进行中…」。
- **统计来源**：`useFocusStore(selectTodayFocusMinutes)`，从持久化 `focus_sessions` 现算（`src/ui/stores/focus-store.ts`，只统计 `completed` 且本地日为今天的会话，按 `actualMinutes ?? durationMinutes`）。
- **点击行为**：`onOpenFocus` → `useFocusOverlayStore.openOverlay()` → 渲染 `FullscreenFocus.tsx`。

### 2.4 音乐栏 LofiHud

- **做什么**：右下角真实音乐播放器。上一首/播放暂停/下一首、曲目列表弹层、顺序/随机切换、均衡器动画。播放状态与 Audio 元素住在 `music-store`（模块级单例，切面板不断）。
- **数据**：曲目来自设置的音乐目录（`settings.paths.musicDir`），通过 `listMusic()`（Rust `audio_list_music`）扫描；文件经 `readMusicBytes` 读取为 Blob 播放。
- **三态显示**：显示「自定义背景音乐 · 循环」（天气自定义歌在播）、内置环境音标签（如「书房 · 雨声」）、或「未配置音乐目录」提示。
- **Store**：`src/ui/stores/music-store.ts`（含 `mimeByExtension`、`nextIndex`/`prevIndex` 顺序/随机逻辑）。
- **统一切换**：`toggleBgm` 在 `FullscreenCozyHome.tsx`：背景音乐在播 → 停；音乐库有选中曲 → 播放/暂停；都没播 → 按当前环境配置恢复。

### 2.5 气泡 SpeechBubble + 等待转圈

- **气泡**：`components/SpeechBubble.tsx`，展示一句陪伴内容（来自真实 `companion-store.current` 或本地唤醒语 `showLine` / 宠物提问 `pet-question`）。锚点 `bubbleAnchor` 跟随宠物当前位置（`petRect`，viewport 像素换算成归一化坐标）；未拿到位置时退回场景 manifest 预设锚点（`scene-manifest.ts` 的 `anchors.speechBubble`）。
- **等待转圈**：`components/PetActor.tsx` 中 `generating && !preview` 时渲染 `<span className="pet-spinner">`。`petGenerating` 来自 `companion-store.generating`（调本地模型生成回应期间为 true），转圈出现在宠物右上角，文字生成后消失。

### 2.6 音频四路独立 + 互斥

| 音源 | Store/实现 | 说明 |
|---|---|---|
| 内置环境音 | `src/infrastructure/audio/audio-player.ts` + `audio-library.ts` | `focus_rain / focus_snow / focus_sunny` 白噪声轨道 |
| 天气自定义歌 | `FullscreenCozyHome.playCustom` | 读字节 → Blob → 循环播放 |
| 音乐库 | `src/ui/stores/music-store.ts` | 本地音乐目录播放 |
| 专注音乐 | `src/ui/stores/focus-music.ts` | 专注模式专属背景音乐，会话开始自动播、结束自动停 |

- **互斥**：`src/ui/stores/audio-exclusive.ts` 维护「同一时刻只响一个」——各音源注册停止函数，播放时 `silenceOthers(id)` 停掉其余；同时维护主音量/全局静音，供背景视频等订阅跟随。
- **背景视频音效**：`ImageBackground.tsx` 的「日常_白天.mp4」自带音效，遵守三条静音规则（用户播音乐→静音、进入专注→静音、全停→恢复）。
- **「专注时保持安静」**：`settings.focus.quietDuringFocus`（默认开），专注中停掉环境音/音乐只留专注音乐；关掉则环境音继续放。

## 3. 各功能面板

底部副面板由 `DemoSheet.tsx` 常驻挂载，7 个面板文件在 `src/ui/demo/fullscreen-cozy-home/panels/`。

### 3.1 今天 TodayPanel（`panels/TodayPanel.tsx`）

**功能点**：任务录入（回车即落库）→ AI 自动拆解为多条草稿预览 → 「替换为拆分」或「保留单条」；任务列表支持完成/删除/为此任务开始专注；右栏：今日打卡卡片 + 打卡日历 + 今日摘要 + 今日节律。

| 项 | 内容 |
|---|---|
| Store | `src/ui/stores/todo-store.ts`、`focus-store.ts`、`checkin-store.ts` |
| Use-case | `CreateTodoUseCase`（`application/use-cases/todo/create-todo.ts`，含 `structureGoal / executeDrafts / executeReplaceDrafts`）、`CompleteTodoUseCase`、`DeleteTodoUseCase`、`StartFocusUseCase`、`RecordDailyCheckInUseCase` 等 |
| Repository | `SqliteTodoRepository`（`infrastructure/db/repositories/todo-repository.ts`）、`SqliteFocusRepository`、`SqliteDailyCheckInRepository`（`checkin-repository.ts`） |
| 数据表 | `todos`、`focus_sessions`、`daily_checkins` |
| AI | 拆解走 `TodoStructuringAdapter`（`ai/adapters.ts`）→ `ModelRouter`（`todo_structuring`，fast 层小模型） |

**细节**：
- 录入即 `create({title})` 立即落库并返回，随后 `structureGoal` 只拆不写返回草稿；用户点「替换为拆分」走 `replaceWithDrafts`（事务化「删原任务 + 整批写拆分」，任一失败不丢原任务）。拆分出的多条任务共享 `sourceGoalId`（软连接任务组，无外键）。
- 拆失败（模型不可用/格式错）→ 明确报错并引导「直接加入」，不让录入卡住。
- **今日打卡**：任务进度（当日排期或当日新建任务，全部完成=「今日已学习」）+ 学习进度（`todayMinutes / studyGoalMinutes`，默认 50 分钟）+ **打卡日历**（`components/CheckInCalendar.tsx`，月视图、周一起始、成功日打勾、今天高亮、可翻月）。数据来自 `daily_checkins`，由 `checkin-subscriber` 在任务/专注事件后重算落库。
- 任务不物理删除：今日视图只显示待办 + 当天完成的，历史保留供复盘统计。

### 3.2 专注 FocusPanel + 全屏专注层

**功能点（入口化）**：主页不再展示大计时器，只有「进入专注模式」按钮 + 今日/本周分钟统计。计时发生在全屏专注层。

- **面板**：`panels/FocusPanel.tsx` —— 番茄钟骨架（`cozy-focus-ring--skeleton`）+ 按钮 + 今日/本周统计（`selectTodayFocusMinutes` / `selectWeekFocusMinutes`，从 `focus_sessions` 现算，本周从周一起算）。
- **全屏专注层**：`FullscreenFocus.tsx` —— 选时长（15/25/45/60）+ 开始 → 大倒计时（呼吸动画，`useFocusMode` 每秒重算）；到点不自动判完成，提示「收个尾再点完成」；点「完成这段」后直接退出全屏。ESC/点 X 退出：专注中先弹确认。右下角音量/静音（与主页共享）+ 专注背景音乐开关。空格键：空闲开始 / 专注中暂停恢复。
- **专注音乐**：`useFocusMusicStore`（`src/ui/stores/focus-music.ts`），可在全屏层从「已配置的天气背景」/「音乐库」/「本地文件」挑一首作为专注背景音乐，落 `settings.focus.musicFile`。
- **Store**：`src/ui/stores/focus-store.ts`（倒计时只存 `startedAt` + 时长，剩余秒数由 `use-focus-mode.ts` 按墙上时钟重算，节流/切后台不错）。`focus-overlay.ts` 管全屏开关。
- **Use-case**：`StartFocusUseCase` / `CompleteFocusUseCase` / `AbortFocusUseCase`（`application/use-cases/focus/`）。开始 → `focusPolicy.activate`；完成 → 记录 `focus_sessions`（含 `actualMinutes` 实际分钟）+ 发 `FocusSessionCompleted` 事件 → 陪伴订阅者触发 `focus_complete`、可选播 `completionCue` 提示音、进入休息倒计时（`settings.focus.breakDurationMinutes`）。
- **Repository**：`SqliteFocusRepository`（`focus-repository.ts`）。数据表 `focus_sessions`。
- **低打扰**：专注中 `FocusModePolicy.isActive()` 为真，外部搜索、陪伴提问、AI 主动行为、后台 embedding 全部被拦截。
- **重启恢复**：启动时 `repositories.focus.abortStaleActive(24)` 回收幽灵会话，再 `findActive()` 恢复活动会话进策略。

### 3.3 知识/检索 KnowledgePanel（`panels/KnowledgePanel.tsx`）

**功能点**：三栏视图（检索 / 笔记整理 / 快速导入）。
- **检索**：搜索框 → 本地向量+关键词混合检索 → 命中列表（标注笔记标题 + 章节面包屑 + 相关度，点开看完整笔记）；「深度检索」开关（LLM Multi-Query + HyDE）；「深度回答」按钮（Self-RAG）；最近搜索 chips；猜你还想搜索；外部搜索结果（可「保存为笔记」）；问答历史（可回看/删除）。
- **笔记整理**：时间线按月→按日分组，每月「归纳本月」生成小结；全部笔记列表（查看/删除）。
- **快速导入**：粘贴文本或选文件（桌面端 PDF/MD/TXT/EPUB/MOBI/AZW3），导入后后台切块建索引。

| 项 | 内容 |
|---|---|
| Store | `src/ui/stores/note-store.ts`（检索结果/外部结果/深度问答/问答历史/按月归纳全在这）、`knowledge-link-store.ts` |
| Use-case | `SearchNotesUseCase`（`application/use-cases/note/search-notes.ts`）、`AskNotesUseCase`（`ask-notes.ts`）、`ImportNoteUseCase`（`import-note.ts`）、`DeleteNoteUseCase`、`EnhanceSearchResultsUseCase`、`SaveAskSessionUseCase` / `ListAskSessionsUseCase` / `DeleteAskSessionUseCase` |
| Repository | `SqliteNoteRepository`（`note-repository.ts`）、`SqliteAskSessionRepository`（`ask-repository.ts`）、`SqliteSettingsRepository`（搜索历史） |
| 数据表 | `notes`、`note_chunks`、`note_chunk_embeddings`（向量虚拟表）、`note_chunks_fts`（FTS5）、`ask_sessions`、`background_jobs` |
| AI 层 | `NoteSearchAdapter` → `RAGOrchestrator.retrieve`；`DeepQAAdapter` → `SelfRag`；`MonthlyDigestAdapter`（按月归纳）；`SearchResultEnhancerAdapter`（结果整理） |

**导入链路**：选文件 → Rust `file_import_into_data_dir`（复制进数据目录）→ `importNote` → `FileImportService.parse`（按扩展名分派 pdf-extract / lib-epub+mobi / markdown / text）→ SHA-256 去重 → 保存 `notes(indexStatus=pending)` → 发 `NoteImported` 事件 → `note-index-subscriber` 入队后台任务 `parse_note → chunk_note → embed_chunks`（`infrastructure/background-jobs/`），断点续传（`background_jobs` 表 + `recoverStaleJobs`）。

### 3.4 复盘 ReviewPanel（`panels/ReviewPanel.tsx`）

**功能点**：日/周/月一个整体 segmented 控件（既决定生成类型也过滤展示）；「生成 X 复盘」按钮；最近复盘展示（内容 + insights + 下一步）；历史列表可展开/逐条删除；`ReviewGenerated` 事件订阅刷新。

| 项 | 内容 |
|---|---|
| Store | `src/ui/stores/review-store.ts` |
| Use-case | `GenerateDailyReviewUseCase` / `GenerateWeeklyReviewUseCase` / `GenerateMonthlyReviewUseCase`（`application/use-cases/review/`）、`DeleteReviewUseCase` |
| Repository | `SqliteReviewRepository`（`review-repository.ts`） |
| 数据表 | `review_logs`（`(review_type, date)` 唯一索引 UPSERT 覆盖） |
| AI 层 | `ReviewGeneratorAdapter`（`ai/adapters.ts`）→ `ModelRouter`：`review_daily`（coach 大模型）走 `review-daily.v1` prompt + `review-log.v1` schema；`review_weekly/monthly`（deep 14b） |

**流程**：点生成 → store → use-case 聚合日期窗口内 `todos` + `focus_sessions`（日=1 天/周=7 天/月=30 天）→ `ReviewGeneratorPort.generate` → 草稿 → `confirmAndCommit` 确认门 → 落库（UPSERT 覆盖）→ 发 `ReviewGenerated`。重新生成即覆盖；AI 生成的复盘一律经确认门，无后台静默写入。模型失败降级为「数据摘要骨架」让用户自己写。

### 3.5 陪伴 CompanionPanel（`panels/CompanionPanel.tsx`）

**功能点**：复用 `PetActor` 展示当前陪伴动画（这里用 `SpriteRenderer` 展示第 8 组动作「认真查看问题」5 帧循环）；「叫一下它」（走真实 `trigger('user_invoked')`，策略可能保持静默并明确写出）；「暂时关掉/重新打开」（改 `settings.companion.enabled`）；「问个问题」（宠物气泡冒一个本地苏格拉底小问题，来自 `pet-question.ts` 的 `SOCRATIC_QUESTIONS`）；当前互动支持内联回应/「稍后」；右侧真实互动历史。

| 项 | 内容 |
|---|---|
| Store | `src/ui/stores/companion-store.ts`、`settings-store.ts`、`pet-question.ts` |
| Use-case | `TriggerInteractionUseCase`、`HandleUserResponseUseCase`、`ProactiveCompanionTickUseCase`（`application/use-cases/companion/`） |
| Repository | `SqliteCompanionRepository`（`companion-repository.ts`） |
| 数据表 | `companion_interactions` |
| AI 层 | `CompanionQuestionAdapter` → `InteractionGenerator`（`ai/companion/interaction-generator.ts`），`companion_dialogue`（fast 1.5B，≤30 字，超长回退模板 `fulilianVoice`） |
| 策略 | `InteractionPolicy`（`application/policies/interaction-policy.ts`）+ `FocusModePolicy`（专注中不打扰） |

### 3.6 对话（写信 / Flora）LetterPanel（`panels/LetterPanel.tsx`）

**功能点**：顶部写一句 → Flora 实时回信；历史按月份归纳成一段段「信封」，点开信封看对话往来；每次打开面板触发每日一次 30% Flora 主动来信抽签。

| 项 | 内容 |
|---|---|
| Use-case | `WriteLetterUseCase`（实时回信）、`ProcessLettersUseCase`（补发排队信）、`GenerateIncomingLetterUseCase`（每月鼓励信 + 每日 30% 抽签）、`ListLettersUseCase`（`application/use-cases/flora/`） |

## 6. AI / Agent 层

AI 层装配与端口在 `src/ai/index.ts`；模型调用唯一入口是 `ModelRouter`；业务层只认 `application/ports.ts` 定义的端口，由 `ai/adapters.ts` 适配。

### 6.1 模型路由 ModelRouter

- **文件**：`src/ai/router/model-router.ts`、`tier-config.ts`、`model-config.ts`。
- **功能**：所有模型调用的唯一入口。选层级 → 检查可用性 → 调模型 → 解析 JSON → Schema 校验（`json-validator.ts`）→ 失败同层重试 1 次 → 降级到 `TIER_FALLBACK` 下一层 → 仍失败返回 `ok=false`，由调用方转人工/模板。
- **层级**（`tier-config.ts` 的 `defaultTierConfigs`）：

| 层 | 默认模型 | 上下文 | 典型任务 |
|---|---|---|---|
| fast | `qwen2.5:1.5b` | 8K | 意图识别、Todo 结构化、检索词生成、陪伴对话、情感分析、验证 |
| coach | `qwen2.5:7b` | 16K | 目标拆解、苏格拉底提问、关系判断、每日复盘、深度问答生成/评判 |
| deep | `qwen2.5:14b` | 32K | 每周/每月复盘、长文档分析、Flora 回信 |

- **任务路由表**：`TASK_ROUTES`（taskType → tier + prompt + schema + requiresJson）。降级链：fast 失败升 coach；coach/deep 失败退 fast。
- **模型名解析**：`model-config.ts` 单例（fast→小模型名，coach/deep→大模型名），设置里改无需重启；`settings-store.updateModels` 调 `setModelConfig` 同步。
- **模型调用日志**：每次调用写 `model_runs` 表（`SqliteModelRunRecorder`，`support-repositories.ts`），`validationResult` 记录 passed/failed/skipped。

### 6.2 RAG 检索（rag-orchestrator + note 检索）

- **编排**：`src/ai/rag/rag-orchestrator.ts` —— `retrieve()`（纯检索不调模型）/ `findConnections()`（检索 + 关系判断）/ `chunk()`（切块）。
- **检索策略**：`src/ai/rag/retrieval-strategy.ts` —— 规则层（标签/关键词/同源/同日打分）+ 向量层（KNN）两层召回合并；查询展开（`query-expansion.ts` 启发式，深度检索用 `query-rewriter.ts` LLM Multi-Query + HyDE）；子块→父块合并（`promoteSiblingChunks`，同章节最多每 2 段一组、上限 2000 字）；深度检索模型重排（`rerank.ts` 生成式 + 可选 `llama-cpp-rerank-provider.ts` cross-encoder）；笔记轮询（每篇最多 3 段）。
- **规则层候选来源**：`src/infrastructure/rag/note-candidate-provider.ts` —— 用 SQL LIKE/FTS 把候选集缩小到内存可打分规模，落空时给向量层留一批最近 chunk。
- **关系判断**：`src/ai/rag/relation-judge.ts` —— 大模型对候选判断关系（`rag-relation.v1` prompt + `knowledge-link.v1` schema），建议经确认后写 `knowledge_links`。
- **切块策略**：`src/ai/rag/chunk-strategy.ts` —— Markdown 按标题层级切（保留 headingPath）；PDF/文本按段落聚到目标 800 字、上限 1500、下限 200。

### 6.3 自我评判 Self-RAG（深度问答）

- **文件**：`src/ai/rag/self-rag.ts`。
- **功能**：深度检索取相关片段 → 本地模型生成草稿（`deep_qa_generate`，coach 自由文本，流式输出）→ 自我评判（`deep_qa_critic`，coach，`qa-critic.v1` schema：相关性/有据/幻觉风险/质量）→ 不达标带评判意见重生成一次（`maxRefine=1`）→ 返回「回答 + 引用来源 + 置信度」。置信度 = `relevance*0.6 + quality/10*0.4`；引用按评判器 `used_chunk_ids` 对齐候选集。模型不可用降级为「最相关片段」。
- **入口 UI**：知识面板搜索框旁「深度回答」按钮 → `note-store.askQuestion` → `AskNotesUseCase` → `DeepQAAdapter` → `SelfRag.ask`。

## 7. 笔记「检索」完整链路（专题回答）

从知识面板搜索框到向量库的完整链路如下：

```
知识面板搜索框 (panels/KnowledgePanel.tsx: submitSearch)
  → useNoteStore.search(query)                      (ui/stores/note-store.ts)
  → useCases.searchNotes.execute(query, 10, 'user_explicit', deep)   (application/use-cases/note/search-notes.ts)
  → ai.noteSearch.search(query, limit, deep)        (ai.ports.noteSearch = NoteSearchAdapter, ai/adapters.ts)
  → rag.retrieve({ text, deep }, limit)             (ai/rag/rag-orchestrator.ts)
  → RetrievalStrategy.retrieve(query, ruleCandidates, limit)   (ai/rag/retrieval-strategy.ts)
       ├─ 规则层候选: candidateProvider.listCandidates(query, limit)
       │    = NoteCandidateProvider (infrastructure/rag/note-candidate-provider.ts)
       │    → SqliteNoteRepository.searchChunks / listChunksForRetrieval
       │       (infrastructure/db/repositories/note-repository.ts, 查 note_chunks + note_chunks_fts)
       ├─ 向量层: embeddingProvider.embed(变体) → vectorStore.query(vector, k)
       │    = SqliteVecProvider (infrastructure/vector-store/sqlite-vec-provider.ts, 查 note_chunk_embeddings)
       ├─ 打分: 规则分×0.4 + 向量分×0.6, minScore 0.18
       ├─ 子块→父块合并 (promoteSiblingChunks)
       ├─ 深度检索时: QueryRewriter(LLM Multi-Query+HyDE) + ReRanker/cross-encoder 重排
       └─ 笔记轮询 (每篇最多 maxChunksPerNote=3 段)
  → SearchNotesResult 回 store: hits / externalResults / confirmationRequired / localLowConfidence
  → 渲染命中列表 (KnowledgePanel 的 cozy-hit-list, 或深度回答的引用来源)
```

**外部搜索补充**：本地结果 < 3 条且允许联网时触发。`SearchNotesUseCase` 先过 `FocusModePolicy` + `PrivacyPolicy` 裁决；需确认时返回 `confirmationRequired`，用户在 UI 点「确认搜索网络」→ `executeWithConfirmation` → `SearchGate.search`（`src/ai/search/search-gate.ts`）→ `KeywordGenerator`（fast）生成关键词 → `search-providers.ts` 按 `search-config` 选引擎 → Rust `search_fetch` 抓 HTML → `ResultFilter`（fast）过滤排序。外部结果不落库，点「保存为笔记」才走 `ImportNoteUseCase`。

**深度回答（Self-RAG）链路**：

```
知识面板「深度回答」按钮
  → useNoteStore.askQuestion(question)               (ui/stores/note-store.ts)
  → useCases.askNotes.execute(question, { deep: true, onToken })   (application/use-cases/note/ask-notes.ts)
  → ai.ports.deepQA.ask = DeepQAAdapter → SelfRag.ask (ai/rag/self-rag.ts)
       ├─ rag.retrieve({ text, deep: true }, 6)      ← 同一 RAG 链路, 深度模式
       ├─ generate (deep_qa_generate, coach)         流式 onToken 逐字回传
       ├─ criticize (deep_qa_critic, qa-critic.v1)    自我评判
       └─ 不达标带意见重生成一次 → 输出 answer+citations+confidence
  → 落库 ask_sessions (saveAskSession)               (application/use-cases/ask/save-ask-session.ts)
  → 渲染: streamingAnswer 流式 → deepAnswer(回答+置信度+引用来源)
```

## 8. 数据层

### 8.1 SQLite 数据库位置

- **默认位置**（Windows）：`%APPDATA%\com.nativemind.app\nativemind.db`。
- 目录内还有 `imports/`（导入副本）、`backups/`（每日 `nativemind.db.bak`，VACUUM INTO 快照）、`extensions/`（sqlite-vec 的 `vec0.dll`）、`paths.json`（存储地址覆盖配置）。
- 存储地址可在 设置 → 路径 修改，改动会连同数据库/导入/备份迁移到新目录并热替换连接（Rust `resolve_data_dir` + `file_set_app_paths`）。
- **Rust 侧**：`src-tauri/src/lib.rs` 打开连接（不跑迁移，迁移由前端 `Database.migrate()` 驱动）；`src-tauri/src/db/connection.rs`；IPC 命令 `db_select / db_execute / db_backup` 等（`src-tauri/src/commands/db.rs`）。
- **TS 侧**：`src/infrastructure/db/database.ts`（`Database` 类 + `SqlDriver` 抽象 + 迁移执行 + 列映射工具）；Tauri 下驱动 `src/infrastructure/db/tauri-driver.ts` 走 IPC；浏览器内存驱动在 `src/infrastructure/local-demo.ts`。
